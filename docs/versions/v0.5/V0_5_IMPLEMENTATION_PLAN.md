## 1. 完成目標

v0.5 要把第一趟遠航累積的發現，轉化為能長期收藏、居住與回望的共同系統：

```text
以新發現累積永久潮光
→ 達到門檻後在目前港口購買新船
→ 切換具獨立外觀、室內與家具目錄的船隻
→ 以稍快航速再次往返已開放海域
→ 由真實遊戲事件形成魚類初遇、永久日誌與今日潮記
→ 購買靜潮自動釣架，在目前停泊港口進行有限離線釣魚
→ 返回遊戲後安全入帳並閱讀一篇安靜的離線摘要
```

完成後，v0.6～v0.9 新海域只需新增內容資料與區域視覺，不必重新設計船隻、潮光、日誌或離線釣魚基礎。

## 2. 範圍與非目標

### 2.1 v0.5 必須完成

- 存檔升級至 v5，保留 v1～v4 遷移鏈、一般／開發者隔離與遷移前逐字備份。
- 建立可去重的正規化遊戲事件層，讓潮光、日誌、每日目標、居民委託、研究與成就使用同一筆事實。
- 建立永久累積、不消耗的潮光與來源帳本。
- 建立六艘船的資料骨架，完整實作前三艘的購買、切換、航速、外觀、室內與船別家具。
- 建立魚類初遇短句、永久航海日誌、每日潮記與舊潮記封存。
- 建立全局靜潮自動釣架、固定種子離線結算與安全回報。
- 補齊集中式開發者控制、資料驗證、單元測試、完整 Chromium 流程、390px 驗收及長期壓測。

### 2.2 v0.5 明確不包含

- 不製作霧岬寒流水道以後的新海域、魚類或居民內容。
- 不回溯補發既有測試存檔的潮光、魚類初遇短句或過往日誌。
- 不重新平衡既有魚價、釣竿、魚餌、每日獎勵與既有家具價格；先以測試數據驗證。
- 不加入船隻能力、家具加成、遠端派遣、日誌編輯、閱讀獎勵或自動發現新收藏。
- 不製作高畫質手繪替換圖；前三艘船延續正式的 HTML／CSS／SVG 程式化視覺。

## 4. 建議模組邊界

```text
src/
├── data/
│   ├── ships.js                 # 六艘船、門檻、價格、航速與視覺描述
│   ├── ship-furniture.js        # 船別商品、插槽類別與場景座標
│   ├── tideglow.js              # 潮光來源與分值
│   └── journal-templates.js      # 人工句庫、初遇與摘要模板
├── systems/
│   ├── game-events.js           # 正規化、序號、分派與消費確認
│   ├── tideglow.js              # 里程碑去重與來源帳本
│   ├── ships.js                 # 購買、切換、航速與資格
│   ├── ship-interiors.js        # 船別家具擁有、插槽與顯示狀態
│   ├── journal.js               # 永久頁、今日潮記、封存與未讀
│   └── auto-fishing.js          # 設定、固定 seed、離線結算與停止原因
├── persistence/
│   ├── save-schema.js           # SAVE_VERSION = 5
│   └── migrations.js            # v4→v5 正規化與既有遷移鏈
└── ui/
    ├── ship-store-view.js
    ├── ship-interior-view.js
    ├── journal-view.js
    └── offline-fishing-view.js
```

拆分原則：

1. 資料檔只宣告內容，不讀寫 DOM 或存檔。
2. 系統函式接收狀態並回傳結果，不自行顯示 modal。
3. UI 只呼叫系統規則，不重算價格、潮光、航速、魚池或離線成果。
4. `src/data.js`、`src/core.js` 與 `src/game.js` 保留相容入口，再依 Slice 逐步轉接。
5. 所有船、家具、事件類型、日誌模板與引用 ID 必須通過啟動時資料驗證。

## 5. 正規化事件契約

### 5.1 事件資料

每筆有意義行為只在狀態變更成功後建立一次事件：

```js
{
  eventId: "event:184",
  sequence: 184,
  type: "fish.discovered",
  source: "manual",
  occurredAt: "2026-07-18T08:30:00.000Z",
  sailingDay: 12,
  timeId: "dawn",
  weatherId: "sunny",
  regionId: "luminous_archipelago",
  spotId: "luminous_shallows",
  shipId: "drifting_home",
  refs: { fishId: "example_fish" },
  payload: {}
}
```

- `eventId` 在原始操作成功時產生，重載或重送不得更換。
- `source` 至少區分 `manual`、`auto`、`offline`、`migration` 與 `developer`。
- 沒有對應值的欄位使用 `null` 或省略，不以空字串偽造內容。
- 事件先保存再分派；任何單一消費者失敗不得讓同一遊戲成果重複入帳。
- 舊入口以相容包裝發出相同事件，不在單一切片全面改寫全部規則。

### 5.2 去重與保留

- 潮光以永久 `sourceId` 帳本去重；來源數量由正式內容控制，不依事件佇列永久保留。
- 永久日誌頁保存原始 `eventId`，相同事件不可建立第二頁。
- 每日目標、居民委託與成就依既有 instance／claim 狀態保持冪等。
- 事件 inbox 只保存尚未被所有消費者確認的項目；確認後可移除，不將無限事件流水塞入存檔。
- 開發者可查看最近事件與各消費者結果，但一般玩家不顯示技術記錄。

## 6. 潮光與船隻契約

### 6.1 潮光來源

| 首次世界里程碑 | 潮光 | 去重來源範例 |
|---|---:|---|
| 發現新魚種 | 1 | `fish:{fishId}` |
| 首次抵達海域 | 5 | `arrival:{regionId}` |
| 正式觀察 | 3 | `observation:{subjectId}` |
| 完成研究節點 | 2 | `research-node:{nodeId}` |
| 完成區域研究 | 5 | `region-research:{regionId}` |
| 居民故事里程碑 | 1 | `resident-story:{residentId}:{milestoneId}` |

- 潮光永不消耗、不能販售，也不因購船或購物下降。
- 重複捕魚、熟悉／精通、每日目標、重複委託與自動釣魚不給潮光。
- 現有兩海域的新存檔完整遊玩預估可累積 75～85 潮光。
- v4 舊存檔初始化為 0；只有遷移後新發生的首次里程碑開始給予潮光。

### 6.2 六艘船

| 船隻 | v0.5 狀態 | 潮光門檻 | 金幣價格 | 航速倍率 |
|---|---|---:|---:|---:|
| 漂流小屋 | 完整實作、初始擁有 | 0 | 免費 | 1.00 |
| 潮聲居所 | 完整實作 | 20 | 1,800 | 1.06 |
| 遠航書房 | 完整實作 | 50 | 4,200 | 1.12 |
| 微光水室 | 僅預告 | 90 | 後續版本定案 | 1.18 |
| 世界船屋 | 僅預告 | 140 | 後續版本定案 | 1.24 |
| 星潮博物艙 | 僅預告 | 200 | 後續版本定案 | 1.30 |

航程時間計算：

```text
實際航程毫秒 = 航線基礎毫秒 ÷ 目前船隻航速倍率
```

- 所有航線都能以漂流小屋完成；後期船隻只有小幅航速成長，不提供魚率、價格、潮光或研究加成。
- 只有停泊於已實作港口時可購買或切換；航行中與外海只能查看。
- 達到潮光門檻時只顯示一次安靜揭露，購船仍需金幣。
- 購買按鈕使用「購買並使用」；確認視窗說明家具需另購，成功後立即切換。
- 古海圖、航程卡、港口、海上場景、船屋、離線回報與商店都透過同一目前船隻 resolver 顯示。

## 7. 船別室內與家具契約

| 船隻 | 外形 | 室內語言 |
|---|---|---|
| 漂流小屋 | 緊湊單桅、小型船艙 | 舊木、補丁布簾、小方窗 |
| 潮聲居所 | 寬船身、圓窗、生活甲板 | 淺木、藍綠織物、圓窗、茶桌 |
| 遠航書房 | 修長雙桅、高窗書艙 | 深木、高窗、黃銅與書房細節 |

- 三艘船都有相同家具插槽類別與容量，但場景座標可不同。
- 同類別家具必須按船型獨立設計，使用不同商品 ID、名稱、視覺、購買狀態與配置。
- 切換船隻後，海灣商店同步切換為目前船隻的家具目錄。
- 家具價格以漂流小屋同類商品為基準：潮聲居所 `+15%`、遠航書房 `+30%`，四捨五入至最接近的 10 金幣。
- 船隻與家具皆為永久固定價格，不輪替、不打折，也不隨現實日期、航海日、天氣或潮光改價。
- 新船不附可替換家具；基本睡眠平台、航圖／日誌入口與水族箱基座是固定結構，空艙仍能使用核心功能。
- 每艘船獨立保存家具擁有、插槽配置、燈光及展示外框。
- 水族箱標本、排列與容量全局共用，不複製魚；船隻只切換外框、位置與光影。
- 切船使用 1～2 秒柔和淡出、船影與低音量木鈴／繩索聲，不阻塞存檔。

## 8. 航海日誌契約

### 8.1 魚類初遇

- 每種魚在 v0.5 後第一次發現時，於魚類圖鑑保存一句人工模板組成的初遇短句。
- 只有稀有等級以上魚類建立額外的 2～3 句永久初遇頁。
- 一般與少見魚不建立空白日誌連結。
- v4 舊存檔既有魚種不回溯補寫；遷移只建立日誌開篇：「今天，我開始把走過的潮聲整理成冊」。

### 8.2 永久頁與今日潮記

永久頁包含：

- 每條航線第一次去程與第一次返程。
- 首次抵達、正式觀察、主要研究節點與區域研究完成。
- 居民故事、首次購買船隻、區域完成與世界完成。
- 稀有等級以上魚類初遇。
- 重複航程中的第一次使用新船、第一次離線抵達、特殊天氣／現象或重要里程碑返航。

每個航海日最多一篇「今日潮記」草稿，整合當日閃光、尺寸紀錄、特殊天氣、區域事件與有意義重訪，再加入一句符合當日狀態的人工詩意描述。換日後封存且不可改寫。

- 永久頁永不刪除。
- 今日潮記最多保留 180 篇；更舊內容每 10 個航海日依區域整理成一篇人工模板摘要。
- 事件發生時立即生成並保存完整文字，日後修改模板不改寫舊回憶。
- 若其他 modal 或故事正在顯示，只延後新增頁提示，不延後資料保存。
- 所有船都有固定且免費的日誌入口；不新增底部導航。
- 支援時間、海域、魚類、居民、研究、船隻、航線、永久頁與每日潮記篩選，並可由相關畫面交叉跳轉。
- 日誌完全唯讀，沒有刪除、編輯、收藏標記或閱讀獎勵。

## 9. 靜潮自動釣架契約

### 9.1 解鎖與設定

- 玩家必須先購買「潮聲居所」，才能在海灣商店以 1,500 金幣購買全局靜潮自動釣架。
- 釣架只購買一次，所有船共用；各船使用符合船型的固定視覺位置，不列入一般家具插槽。
- 只能在目前船隻已停泊時啟用。
- 只能選擇目前停泊港口所屬海域內、已造訪且可釣魚的釣點，以及玩家現有魚餌。
- 不允許選擇任意已造訪的遠端釣點；出航、離港或切換停泊海域會先安全停止／結算目前設定。

### 9.2 離線結算

- 只有頁面完全關閉後的時間計入；頁面開啟、隱藏分頁或背景分頁不累積。
- 一次最多結算 3 小時；魚餌先耗盡時立即停止，不提供溢出補償。
- 每次捕獲消耗一份所選魚餌。
- 建立設定時保存固定 seed、開始時間、釣點、海域、船隻與魚餌；重載不得重抽結果。
- 成果校準為同條件手動釣魚約 50%，只包含該釣點已發現的一般／少見魚。
- 不取得未知魚、稀有以上魚、閃光、正式觀察、奇景或尺寸紀錄。
- 只增加漁獲庫存與有限熟悉度；不增加手動總捕獲計數，也不推進區域印章、潮光、捕獲型每日目標、居民捕獲委託、事件、成就或永久日誌。
- 玩家日後手動販售自動漁獲時，該販售行為仍可依現有規則推進販售型目標。

### 9.3 回報安全性

離線成果必須先以單一冪等交易加入存檔，再顯示摘要；關閉摘要、重整或重開遊戲不得重複入帳。摘要包含離線時間、地點、魚餌消耗、總數、魚種、估計價值、熟悉度與停止原因，最後加入一句人工模板詩意描述，但不建立永久日誌頁。

## 10. v5 存檔與遷移契約

### 10.1 建議狀態邊界

```js
{
  version: 5,
  gameEvents: {
    nextSequence: 1,
    pending: []
  },
  tideglow: {
    total: 0,
    ledgerBySourceId: {}
  },
  ships: {
    activeShipId: "drifting_home",
    ownedShipIds: ["drifting_home"],
    purchasedAtByShipId: {},
    revealedShipIds: ["drifting_home"],
    interiorsByShipId: {}
  },
  journal: {
    introCreated: true,
    fishEncounterLineById: {},
    permanentEntries: [],
    dailyEntries: [],
    dailyArchives: [],
    unreadEntryIds: []
  },
  autoFishing: {
    owned: false,
    activeSession: null,
    lastSummary: null
  }
}
```

實際欄位名稱可在 Slice A 依既有正規化風格微調，但不得改變資料所有權：水族箱與魚類收藏維持全局，家具配置按船隻分開，事件 inbox 不作永久歷史資料庫。

### 10.2 v4→v5 規則

1. 第一次遷移前，把原始 v4 JSON 逐字保存至對應一般或開發者備份鍵。
2. 寫回主要鍵前，先把候選 v5 JSON 寫入同模式暫存鍵並重新解析、驗證；主要鍵更新成功後移除暫存。配額不足或驗證失敗時保留原主要檔與備份，不留下半套 v5 狀態。
3. 保留魚類、尺寸、閃光、漁獲、水族箱、金幣、魚餌、釣竿、成就、每日目標、居民委託、居民故事、研究、區域、航線、事件、偏好與世界位置。
4. 既有家具擁有與插槽配置映射至「漂流小屋」，不複製到其他船。
5. 潮光初始化為 0，只擁有並使用漂流小屋。
6. 建立唯一日誌開篇，不回溯魚類初遇或歷史事件。
7. 靜潮自動釣架初始化為未購買、未啟用且無待結算成果。
8. v1～v3 先通過既有遷移鏈正規化，再套用 v5 規則。
9. 重複執行遷移必須得到相同結果；v5 缺少可選欄位時可補正，但不得覆寫合法玩家狀態。

## 19. 測試與效能預算

### 19.1 存檔大小

- 一般成熟存檔目標：JSON 小於 `500 KB`。
- 長期壓測硬上限：單份 JSON 小於 `1.5 MB`。
- 上限保留主要存檔、遷移前備份與寫入中暫存共存的安全空間；不得把 1.5 MB 當成日常使用目標。
- 超過 500 KB 先檢查重複事件、重複文字、全局資料被複製到各船及已確認 inbox；不可刪除永久收藏成果掩蓋問題。

### 19.2 壓測情境

- 連續輸入至少 500 筆正規化事件，所有潮光與日誌結果保持去重。
- 建立並封存 180 篇今日潮記，觸發十日摘要後重新載入。
- 在三艘船之間切換 300 次，家具、水族箱、商店、DOM 與監聽器保持正確。
- 執行 240 次離線釣魚結算，包含餌盡、三小時、出航、換港與重載。
- 390px 視窗、最大文字與 UI 縮放無橫向溢位。
- Documents 與事件監聽器不得持續增加；JS heap 增量低於 16 MB，並保留 Slice H 的相對增幅比較。
- 未捕捉瀏覽器例外為 0，所有存檔可再次序列化、遷移與載入。
