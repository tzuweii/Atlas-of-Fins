# Atlas of Fins｜世界航線與海域系統設計

> 文件狀態：世界設定原則已核准；海域名稱、拓撲與數值為設計提案
> 建立日期：2026-07-16
> 建議首個實作版本：v0.4「世界航線基礎」
> 前置版本：v0.3.0-alpha.4，單一海灣、3 個釣點、30 種魚、存檔 v3

## 1. 系統目的

世界航線把目前的單一海灣擴展成一段持續航行的收藏旅程。玩家不是從功能選單隨意切換背景，而是帶著同一艘船屋沿海洋路徑移動、抵達不同港口、遇見當地魚類並把旅程永久留在圖鑑與日誌中。

本系統必須同時解決四件事：

1. 為大量魚種提供清楚的生態與收藏分類。
2. 為長期進度建立「下一片海」的可見目標。
3. 讓船屋、居民、音樂與故事能跟著旅程成長。
4. 在不加入航海壓力的前提下，讓世界移動具有真實感。

## 2. 核准的世界規則

### 2.1 真實洋流與魚類

- 主要海域以真實洋流、緯度、海溫、季風、海岸地形與生態型作為設計基礎。
- 一般魚類使用真實物種，出現區域需有可靠生態資料支持。
- 遊戲可為節奏簡化季節與分布邊界，但不得把明顯寒帶魚任意放入熱帶珊瑚礁而不作解釋。
- 圖鑑文字應區分「真實生態資訊」與「本作架空港口的觀察敘事」。
- 每種魚資料需保留來源註記或研究備忘，正式內容製作時優先參考研究機構、漁業機構與可信物種資料庫。

### 2.2 架空港口與人物

- 國界、城市、港口、島嶼、燈塔與人物不直接對應現實政治實體。
- 港口可融合相同海洋文化帶的建築與生活元素，但應避免把單一真實族群變成裝飾符號。
- 不需要外交、海關、戰爭、殖民、國家聲望或政治任務。
- 地名使用詩意且可辨識生態的命名方式，例如霧、潮、礁、雨木、石岸與星冰。

### 2.3 傳說魚

- 傳說魚是少量例外，不取代真實魚類作為圖鑑主體。
- 出現應與地方自然現象、居民記憶或長期收藏相連，不做高難度 Boss 戰。
- 仍遵守防挫折：線索可累積、條件可重現、失敗不會失去永久進度。
- 現有「月紗皇帶魚」暫列第一條傳說魚候選；正式分類與文案需在區域資料遷移時確認。

## 3. 玩家航行流程

```text
在目前港口或海域打開海圖桌
→ 查看已解鎖航線與遠方預告
→ 選擇可抵達的目的地
→ 確認航程會經過的洋流、預估段落與可能觀察
→ 船屋進入自動航行狀態
→ 觀看或略過航行轉場；沿途產生有限的觀察與日誌
→ 抵達新港口
→ 解鎖區域釣點、魚誌頁、環境聲景與居民場景
→ 完成區域收藏並開啟下一條航線
```

### 3.1 出發

- 只允許前往已解鎖且與目前節點相連的目的地。
- 出發前顯示目的地、航線名稱、環境提示、預期解鎖與是否可立即返回。
- 不消耗燃料或一次性通行證；航線解鎖即永久有效。
- 漁獲、水族箱、家具、稱號、事件歷史與圖鑑全部隨船保留。

### 3.2 航行

- 航行由系統自動完成，不要求玩家手動控制方向、帆角或速度。
- 第一版可使用短轉場與分段文字，不必立即製作即時開放海面。
- 玩家可觀看完整航行氛圍，也可略過至抵達；略過不損失重要收藏。
- 若航行期間提供觀察或自動漁獲，結果在抵達時一次整理，不以倒數通知催促玩家。

### 3.3 抵達與重訪

- 首次抵達必須有海域名稱、主色、環境聲、港口遠景、第一頁日誌與一個可見解鎖。
- 已到訪海域永久記錄，可沿已解鎖航線自由往返。
- 返回舊海域不是退步；不同事件、研究階段、居民來訪與跨區回游魚可提供重訪理由。
- 區域事件與目前海灣事件共用「機會而非期限」原則。

## 4. 海圖結構

### 4.1 節點式而非自由操船

世界海圖由三種節點與航線構成：

| 類型 | 說明 | 主要互動 |
|---|---|---|
| 港口節點 | 安全停靠、居民、商店、船屋改造 | 交談、交易、整理收藏、選擇出航 |
| 海域節點 | 主要釣魚與區域事件空間 | 切換釣點、釣魚、研究、日誌 |
| 航程節點 | 洋流、霧帶、外海或季風過渡 | 觀景、沿途紀錄、短事件 |

v0.4 可先將每個「港口＋相鄰釣場」合併成單一區域節點，等航行內容成熟後再拆出航程節點。

### 4.2 候選拓撲

下列拓撲只表示長期節奏，不代表地理比例：

```text
                         霧岬寒流水道
                        ╱              ╲
初潮海灣 ─────────────                    北大西洋石岸
                        ╲              ╱
                         黑潮珊瑚群島 ─ 季風群島
                                  ╲    ╱
                                星冰南方海
```

建議規則：

- 初始只顯示初潮海灣與兩個遠方方向的模糊輪廓。
- 第一條遠航優先前往黑潮珊瑚群島；寒流路線可稍後解鎖。
- 中期出現分支，但不做永久二選一；玩家最終可走完所有航線。
- 星冰南方海作為長期終點候選，需要多區域研究成果，不需要消耗收藏品。

## 5. 候選主要海域

以下名稱、魚數與港口皆為討論稿；正式實作前需逐區核准並研究魚類分布。

| 順序 | 海域候選名 | 真實海洋基礎 | 架空停靠點 | 視聽特性 | 內容角色 |
|---:|---|---|---|---|---|
| 1 | 初潮海灣 | 西北太平洋亞熱帶沿岸、暖流邊緣 | 初潮港 | 青綠淺海、木船、暖燈、柔浪 | 教學、家的起點、目前 30 種魚 |
| 2 | 黑潮珊瑚群島 | 黑潮暖流、熱帶／亞熱帶礁區 | 綠玻璃礁港 | 透明藍、珊瑚色、明亮打擊與木管 | 第一趟遠航、生態研究員登場 |
| 3 | 霧岬寒流水道 | 親潮與北太平洋寒流水域 | 白霧岬 | 灰藍霧、海鳥、低弦與遠笛 | 冷水魚、燈塔守望者遠訊 |
| 4 | 季風群島 | 印度洋季風、紅樹林與潟湖 | 雨木棧港 | 濕綠、驟雨、木棧、柔和手鼓 | 潮汐濕地、港口生活收藏 |
| 5 | 北大西洋石岸 | 灣流延伸、北大西洋漂流與岩岸 | 風琴石港 | 深靛、長浪、石屋、風鳴和弦 | 遠洋回游、居民故事交會 |
| 6 | 星冰南方海 | 南極繞極流與高緯冷水 | 星落觀測站 | 冰青、長夜、稀疏鋼琴與低頻海聲 | 終點航線、世界圖鑑回望 |

### 5.1 初始海灣的定位調整

目前遊戲中的海灣資料完整保留，v0.4 只把它包進區域層：

- 候選 `regionId`: `first_tide_bay`
- 既有釣點：`shore`、`reef`、`deep`
- 既有魚：30 種，不因區域遷移改變玩家捕獲紀錄。
- 既有海灣事件：仍依航海日運作，事件定義增加區域限制。
- 是否把畫面名稱由「寧靜海灣／海灣」統一為「初潮海灣」，需先經命名決策。

### 5.2 第一個新海域建議

優先選擇黑潮珊瑚群島，原因如下：

- 暖流與現有亞熱帶海灣能自然銜接。
- 部分既有魚可跨區出現，能立即驗證一魚多棲地資料模型。
- 珊瑚礁魚的輪廓與色彩差異大，第一趟旅行的視覺回報明確。
- 可合理導入生態研究員、區域研究頁與新的圖鑑篩選。
- 不需先完成寒帶霧景、冰面或高成本開放海動畫。

建議內容包：2～3 個釣點、12～15 種新增魚、3～5 種跨區魚、1 個港口紀念物、1 組區域研究頁、1 段居民初遇、1 組環境聲景與音樂主題。

## 6. 魚類與棲地資料模型

### 6.1 從單區欄位遷移為多棲地

目前魚類使用全域 `spots`、`times`、`weather` 與 `baits`。世界版本改為 `habitats`，同一種魚可在多個海域擁有不同權重與條件。

```js
{
  id: "horse_mackerel",
  name: "竹筴魚",
  origin: "real", // "real" | "legendary"
  habitats: [
    {
      regionId: "first_tide_bay",
      spotIds: ["shore", "deep"],
      timeIds: ["dusk", "night"],
      weatherIds: ["sunny", "rain"],
      baseWeight: 1,
      sizeScale: 1,
      noteId: "horse_mackerel_first_tide"
    },
    {
      regionId: "kuroshio_coral_islands",
      spotIds: ["current_edge"],
      timeIds: ["dawn", "dusk"],
      weatherIds: ["sunny"],
      baseWeight: 0.7,
      sizeScale: 1.08,
      noteId: "horse_mackerel_kuroshio"
    }
  ]
}
```

規則：

- `regionId` 與 `spotIds` 必須存在於區域資料。
- 魚種至少有一個合法棲地，且每個棲地至少存在一組可捕獲條件。
- 魚餌偏好與行為可先維持全域；只有確有必要才做區域覆寫。
- `sizeScale` 用於區域尺寸差異，第一版預設為 `1`，避免過早複雜化。
- 圖鑑總發現以 `fishId` 計算，同種魚跨區不重複增加總魚種數。
- 區域圖鑑另記錄該魚是否曾在當地捕獲，形成回訪收藏。

### 6.2 生態資料責任

新增真實魚類時必須記錄：

```js
research: {
  sourceLabels: ["來源名稱"],
  sourceUrls: ["https://..."],
  checkedAt: "YYYY-MM-DD",
  distributionNote: "採用此海域與條件的理由",
  gameplaySimplification: "為遊戲節奏做過的簡化"
}
```

研究資料可在發行版建置時移除，但專案內需保留，避免後續擴充失去依據。

## 7. 區域與航線資料模型

### 7.1 區域

```js
const REGIONS = [
  {
    id: "first_tide_bay",
    name: "初潮海灣",
    portName: "初潮港",
    currentProfile: "subtropical_warm_current_edge",
    climateTags: ["subtropical", "coastal"],
    spotIds: ["shore", "reef", "deep"],
    unlock: { type: "default" },
    palette: "first_tide",
    musicId: "bay",
    journalPoolId: "first_tide",
    residentSceneIds: [],
    status: "available"
  }
];
```

### 7.2 區域釣點

```js
const REGION_SPOTS = [
  {
    id: "shore",
    regionId: "first_tide_bay",
    name: "近岸淺水區",
    unlock: { type: "default" },
    sceneVariant: "shore",
    habitatTags: ["coastal", "shallow"]
  }
];
```

v0.4 可保留現有釣點 ID，避免存檔與事件資料大規模遷移。未來不同區域若有同名概念，使用全域唯一 ID，例如 `kuroshio_lagoon`。

### 7.3 航線

```js
const ROUTES = [
  {
    id: "first_tide_to_kuroshio",
    fromRegionId: "first_tide_bay",
    toRegionId: "kuroshio_coral_islands",
    name: "玻璃暖流航線",
    currentTags: ["warm_current"],
    unlock: { type: "research", researchId: "first_tide_departure" },
    travelSegments: 3,
    preview: {
      color: "coral_blue",
      silhouetteFishIds: ["unknown_reef_fish_1"],
      musicPreviewId: "kuroshio_hint"
    }
  }
];
```

航線預設為雙向；若故事需要單向首次航程，抵達後必須立即解鎖安全返航，不可把玩家困在新區域。

### 7.4 居民

```js
const RESIDENTS = [
  {
    id: "lighthouse_keeper",
    role: "keeper",
    homeRegionId: "first_tide_bay",
    sceneIds: ["keeper_departure_radio"],
    journalTag: "keeper"
  }
];
```

角色姓名未定時可使用角色型 ID。功能資料與故事文案分離，避免改名影響存檔。

## 8. 世界狀態與存檔

### 8.1 建議新增狀態

```js
world: {
  currentRegionId: "first_tide_bay",
  visitedRegionIds: ["first_tide_bay"],
  unlockedRouteIds: [],
  regionProgress: {
    first_tide_bay: {
      discoveredFishIds: [],
      completedResearchIds: [],
      firstArrivedAt: "ISO-8601"
    }
  },
  travel: null
}
```

航行中：

```js
travel: {
  routeId: "first_tide_to_kuroshio",
  fromRegionId: "first_tide_bay",
  toRegionId: "kuroshio_coral_islands",
  segment: 1,
  startedAt: "ISO-8601",
  observations: []
}
```

### 8.2 存檔遷移

v0.4 若新增 `world`，建議將 `SAVE_VERSION` 升至 v4：

- v1～v3 存檔載入後預設位於初始海灣。
- 現有發現、漁獲、水族箱、事件、稱號、家具與金幣原樣保留。
- 既有魚的全域釣點條件轉譯成初始海灣棲地，不回寫或重置捕獲紀錄。
- 開發者存檔需解鎖全部「目前已實作」區域與航線；不可預先解鎖只有文件、尚無程式的候選海域。
- 不認得的區域、航線或航行狀態必須安全回到最近有效區域，並保留其他收藏資料。
- 主存檔與備份存檔都需測試 v3 → v4 → 再載入。

## 9. 海圖介面需求

### 9.1 入口

- 第一版將海圖桌放在船屋，避免底部主導航立刻增加第六欄。
- 航行中可從釣魚頁或船屋查看簡化航程卡。
- 後續若世界功能使用頻率足夠，再評估獨立主導航。

### 9.2 海圖畫面資訊層級

1. 目前所在海域與船隻標記。
2. 已解鎖且可直接抵達的相鄰節點。
3. 已到訪海域的完成度與區域魚誌。
4. 未解鎖海域的模糊輪廓、魚影、色彩與解鎖方向。
5. 選中航線的說明、預告與出發按鈕。

### 9.3 防壓力呈現

- 不顯示紅色倒數、燃料不足或錯過警告。
- 未解鎖條件以「再完成一頁觀察，風會帶來新的方向」等正向語句呈現。
- 百分比可用於總覽，但主要回饋應是具體收藏與畫面變化。
- 海圖不塞入每條魚的完整資料；詳細生態回到圖鑑查看。

### 9.4 無障礙

- 地圖節點必須同時具有文字標籤、狀態文字與鍵盤焦點，不只依靠顏色或位置。
- 分支航線在窄螢幕可切換為直向卡片清單。
- 航行動畫可略過，並遵守減少動態效果偏好。
- 音樂預告必須有靜音與文字描述替代。

## 10. 海灣事件的區域化

現有三個事件在 v0.4 加入 `regionIds: ["first_tide_bay"]`，避免玩家位於其他海域時仍顯示海灣事件。

長期事件分三層：

| 層級 | 例子 | 保存方式 |
|---|---|---|
| 區域日事件 | 銀潮靠岸、雨後漂流 | 目前航海日事件＋歷史 |
| 航程觀察 | 暖流漂葉、遠方鯨歌 | 航行中的一次性觀察 |
| 世界自然現象 | 洄游季、長夜星潮 | 多區域可見、永久圖鑑紀錄 |

所有事件維持可重現、無懲罰、非限時營運活動的原則。

## 11. 居民在航線中的使用

### 11.1 燈塔守望者

- 初始海灣提供第一條航線方向與返航意象。
- 玩家遠航後可透過收音機收到短訊，使家的存在延續。
- 功能是解釋海況與路徑，不提供大量每日任務。

### 11.2 魚市場老闆

- 是不同港口交易與地方紀念物的生活連結。
- 可透過合作攤位、信件或熟人網絡在遠方被提起，不必本人出現在每一港。
- 價格差異只作風味或小幅收藏動機，不建立跨港套利模擬。

### 11.3 生態研究員

- 適合在第一個新海域登場，將區域圖鑑與研究航線自然帶入。
- 可短期登船，使船屋第一次具有「同行者來訪」的變化。
- 生態資訊以觀察與共同驚喜呈現，不用考題驗證玩家知識。

### 11.4 漂流旅人

- 在多條航線不定期出現，留下小物、短句與更遠海域的線索。
- 出現條件可由已到訪區域與航行次數決定，但不得使用短暫真實時間窗口。
- 玩家錯過當次場景時，日誌或後續航行可再次觸發。

## 12. v0.4 建議開發切片

v0.4 的目標是證明「目前海灣已成為世界的一個區域」，而不是一次完成六片海。

### Slice A｜區域資料層

- 新增 `REGIONS`、`REGION_SPOTS` 與查詢函式。
- 把目前 3 個釣點與 30 種魚掛到初始區域。
- 魚池、事件、圖鑑與場景讀取目前區域。
- 現有遊玩結果在遷移前後保持一致。

### Slice B｜世界狀態與 v4 存檔

- 新增 `world.currentRegionId`、到訪區域與航線狀態。
- 完成 v1～v3 一般／開發者存檔遷移。
- 加入未知區域與損壞航行狀態的安全回復。
- 更新核心單元測試與瀏覽器存檔回歸。

### Slice C｜海圖外殼

- 船屋加入海圖桌入口。
- 顯示初始海灣、船隻位置與未解鎖遠方輪廓。
- 可選取候選航線並查看預告，但未完成內容不可出發。
- 桌面、手機、鍵盤與減少動態效果可用。

### Slice D｜首條航線垂直切片

此切片是否納入 v0.4 或延至 v0.5，待下一輪討論：

- 建立一條測試航線與航行狀態。
- 提供觀看／略過轉場與抵達回報。
- 抵達一個最小新港口外殼，驗證往返與區域切換。
- 不必在同一切片加入完整 12～15 種新魚。

## 13. v0.4 驗收條件草案

- [ ] 現有 30 種魚在初始區域的合法魚池與 alpha.4 完全相容。
- [ ] 三個海灣事件只在初始區域顯示與累積。
- [ ] v1、v2、v3 與開發者存檔載入後位於有效初始區域，收藏無遺失。
- [ ] 海圖正確顯示目前位置、可用節點、鎖定節點與解鎖提示。
- [ ] 鎖定海域不可誤觸進入，且不會建立損壞航行狀態。
- [ ] 若實作航線，出發、略過、抵達、保存、重載與返航皆可完成。
- [ ] 未知區域／航線 ID 可安全修復，不破壞其他存檔資料。
- [ ] 開發者模式只解鎖程式中存在的區域內容。
- [ ] 手機與鍵盤可完整操作海圖；動畫可略過。
- [ ] 核心單元測試、瀏覽器完整流程、語法檢查與未捕捉例外檢查通過。

## 14. 風險與控制

| 風險 | 徵兆 | 控制方式 |
|---|---|---|
| 海圖變成選單換皮 | 抵達前後只有背景不同 | 每區至少綁定魚誌、聲景、收藏物與日誌 |
| 真實生態錯置 | 魚類分布只憑印象 | 保存資料來源與遊戲化簡化說明 |
| 一次設計過多海域 | 所有區域都有名字但沒有可玩內容 | 先完成區域架構與第一趟遠航垂直切片 |
| 存檔遷移破壞收藏 | 現有魚或事件被重設 | 保留全域 fishId，新增包覆層而非重建資料 |
| 航行造成等待壓力 | 玩家被迫等真實時間或定時回來 | 可略過、無倒數懲罰、抵達回報一次整理 |
| 分支造成錯過焦慮 | 選一條路永久失去另一區 | 所有主航線最終可解鎖與自由往返 |
| 居民變成任務機器 | 每港大量驚嘆號 | 每區少量短場景，記錄可回看、不阻塞釣魚 |

## 15. 尚待核准

1. 初始區域、六大海域與港口的正式名稱。
2. 海圖最終拓撲以及每條航線的解鎖順序。
3. v0.4 是否包含可實際抵達的測試港口。
4. 第一新海域是否正式定為黑潮珊瑚主題。
5. 區域圖鑑是獨立分頁、篩選器或世界海圖上的收藏冊。
6. 航行進度使用短動畫、遊戲內段落或真實時間；目前建議不依賴真實時間。
7. 傳說魚的比例、解鎖方式，以及月紗皇帶魚的正式分類。
8. 每個區域的真實魚類清單與生態資料來源。
