# Atlas of Fins｜世界航線與海域系統設計

> 文件狀態：架構參考；正式世界、航程與版本規格見 [`FINAL_GAME_DESIGN.md`](FINAL_GAME_DESIGN.md)
> 建立日期：2026-07-16
> 正式首個實作版本：v0.4「第一趟遠航垂直切片」
> 現行擴充計畫：[`V0_5_IMPLEMENTATION_PLAN.md`](versions/v0.5/V0_5_IMPLEMENTATION_PLAN.md)
> 前置版本：v0.3.0-alpha.4，單一海灣、3 個釣點、30 種魚、存檔 v3
> 覆寫規則：資料模型與遷移原則仍有效；分支拓撲、候選名稱、略過航程、居民跨海互動與待核准清單已由正式定案覆寫

## 1. 系統目的

世界航線把目前的單一海灣擴展成一段持續航行的收藏旅程。玩家不是從功能選單隨意切換背景，而是駕著目前選用的船屋沿海洋路徑移動、抵達不同港口、遇見當地魚類並把旅程永久留在圖鑑與日誌中。

本系統必須同時解決四件事：

1. 為大量魚種提供清楚的生態與收藏分類。
2. 為長期進度建立「下一片海」的可見目標。
3. 讓船屋、居民、音樂與故事能跟著旅程成長。
4. 在不加入航海壓力的前提下，讓世界移動具有真實感。

## 2. 核准的世界規則

### 2.1 真實洋流與魚類

- 主要海域以真實洋流、緯度、海溫、季風、海岸地形與生態型作為設計基礎。
- 一般魚類使用真實物種，出現區域需有可靠生態資料支持。
- 遊戲可為節奏簡化季節與分布邊界，但不得把明顯寒帶魚任意放入熱帶珊瑚礁而不作解釋。
- 圖鑑文字應區分「真實生態資訊」與「本作架空港口的觀察敘事」。
- 每種魚資料需保留來源註記或研究備忘，正式內容製作時優先參考研究機構、漁業機構與可信物種資料庫。

### 2.2 架空港口與人物

- 國界、城市、港口、島嶼、燈塔與人物不直接對應現實政治實體。
- 港口可融合相同海洋文化帶的建築與生活元素，但應避免把單一真實族群變成裝飾符號。
- 不需要外交、海關、戰爭、殖民、國家聲望或政治任務。
- 地名使用詩意且可辨識生態的命名方式，例如霧、潮、礁、雨木、石岸與星冰。

### 2.3 傳說魚

- 傳說魚是少量例外，不取代真實魚類作為圖鑑主體。
- 出現應與地方自然現象、居民記憶或長期收藏相連，不做高難度 Boss 戰。
- 仍遵守防挫折：線索可累積、條件可重現、失敗不會失去永久進度。
- 現有「月紗皇帶魚」暫列第一條傳說魚候選；正式分類與文案需在區域資料遷移時確認。

## 3. 玩家航行流程

```text
在目前港口或海域打開海圖桌
→ 查看已解鎖航線與遠方預告
→ 選擇可抵達的目的地
→ 確認航程會經過的洋流、預估段落與可能觀察
→ 船屋進入自動航行狀態
→ 航程依距離、熟悉度與出航船隻航速推進；沿途產生有限的觀察與日誌
→ 抵達新港口
→ 解鎖區域釣點、魚誌頁、環境聲景與居民場景
→ 完成區域收藏並開啟下一條航線
```

### 3.1 出發

- 只允許前往已解鎖且與目前節點相連的目的地。
- 出發前顯示目的地、航線名稱、環境提示、預期解鎖與是否可立即返回。
- 不消耗燃料或一次性通行證；航線解鎖即永久有效。
- 漁獲、水族箱標本、稱號、事件歷史與圖鑑是全局收藏，會隨目前船隻航行；家具擁有與配置則分別保存在所屬船隻，切換回該船時恢復。

### 3.2 航行

- 航行由系統自動完成，不要求玩家手動控制方向、帆角或速度。
- 第一版可使用分層場景與分段文字，不必立即製作即時開放海面。
- 航程不能瞬間略過；玩家可關閉遊戲，航行仍依真實經過時間正常推進。
- 航行期間可產生不要求操作的被動觀察，結果在抵達時一次整理；航行本身不產生自動漁獲。靜潮自動釣架只在停泊且遊戲完全關閉時運作，出航前必須先停止／結算。

### 3.3 抵達與重訪

- 首次抵達必須有海域名稱、主色、環境聲、港口遠景、第一頁日誌與一個可見解鎖。
- 已到訪海域永久記錄，可沿已解鎖航線自由往返。
- 返回舊海域不是退步；不同事件、研究階段、居民在當地的後續片段與跨區回游魚可提供重訪理由。
- 區域事件與目前海灣事件共用「機會而非期限」原則。

## 4. 海圖結構

### 4.1 節點式而非自由操船

世界海圖由三種節點與航線構成：

| 類型 | 說明 | 主要互動 |
|---|---|---|
| 港口節點 | 安全停靠、居民、商店、船屋改造 | 交談、交易、整理收藏、選擇出航 |
| 海域節點 | 主要釣魚與區域事件空間 | 切換釣點、釣魚、研究、日誌 |
| 航程節點 | 洋流、霧帶、外海或季風過渡 | 觀景、沿途紀錄、短事件 |

v0.4 可先將每個「港口＋相鄰釣場」合併成單一區域節點，等航行內容成熟後再拆出航程節點。

### 4.2 歷史候選拓撲

下列拓撲保留早期分支構想；正式 v1.0 已改為六海域依序解鎖、解鎖後自由往返，見 `FINAL_GAME_DESIGN.md` 第 9～10 節。

```text
                         霧岬寒流水道
                        ╱              ╲
初潮海灣 ─────────────                    北大西洋石岸
                        ╲              ╱
                         黑潮珊瑚群島 ─ 季風群島
                                  ╲    ╱
                                星冰南方海
```

建議規則：

- 初始只顯示初潮海灣與兩個遠方方向的模糊輪廓。
- 第一條遠航優先前往黑潮珊瑚群島；寒流路線可稍後解鎖。
- 中期出現分支，但不做永久二選一；玩家最終可走完所有航線。
- 星冰南方海作為長期終點候選，需要多區域研究成果，不需要消耗收藏品。

### 5.1 初始海灣的定位調整

目前遊戲中的海灣資料完整保留，v0.4 只把它包進區域層：

- 候選 `regionId`: `first_tide_bay`
- 既有釣點：`shore`、`reef`、`deep`
- 既有魚：30 種，不因區域遷移改變玩家捕獲紀錄。
- 既有海灣事件：仍依航海日運作，事件定義增加區域限制。
- 世界版本的正式區域名稱為「眠潮灣」；既有畫面文字於 v0.4 遷移時統一。

### 5.2 第一個新海域定案

第一個新海域正式定為「琉光群島」，以黑潮型暖流與珊瑚礁生態為原型，原因如下：

- 暖流與現有亞熱帶海灣能自然銜接。
- 部分既有魚可跨區出現，能立即驗證一魚多棲地資料模型。
- 珊瑚礁魚的輪廓與色彩差異大，第一趟旅行的視覺回報明確。
- 可合理導入生態研究員、區域研究頁與新的圖鑑篩選。
- 不需先完成寒帶霧景、冰面或高成本開放海動畫。

v0.4 內容包：風棲港、3 個主要釣點、約 15 種區域魚、3～5 種觀察內容、1 個港口紀念物、1 組區域研究頁、澄野初遇與獨立環境聲景／音樂主題。

## 6. 魚類與棲地資料模型

### 6.1 從單區欄位遷移為多棲地

目前魚類使用全域 `spots`、`times`、`weather` 與 `baits`。世界版本改為 `habitats`，同一種魚可在多個海域擁有不同權重與條件。

```js
{
  id: "horse_mackerel",
  name: "竹筴魚",
  origin: "real", // "real" | "legendary"
  habitats: [
    {
      regionId: "first_tide_bay",
      spotIds: ["shore", "deep"],
      timeIds: ["dusk", "night"],
      weatherIds: ["sunny", "rain"],
      baseWeight: 1,
      sizeScale: 1,
      noteId: "horse_mackerel_first_tide"
    },
    {
      regionId: "kuroshio_coral_islands",
      spotIds: ["current_edge"],
      timeIds: ["dawn", "dusk"],
      weatherIds: ["sunny"],
      baseWeight: 0.7,
      sizeScale: 1.08,
      noteId: "horse_mackerel_kuroshio"
    }
  ]
}
```

規則：

- `regionId` 與 `spotIds` 必須存在於區域資料。
- 魚種至少有一個合法棲地，且每個棲地至少存在一組可捕獲條件。
- 魚餌偏好與行為可先維持全域；只有確有必要才做區域覆寫。
- `sizeScale` 用於區域尺寸差異，第一版預設為 `1`，避免過早複雜化。
- 圖鑑總發現以 `fishId` 計算，同種魚跨區不重複增加總魚種數。
- 區域圖鑑另記錄該魚是否曾在當地捕獲，形成回訪收藏。

### 6.2 生態資料責任

新增真實魚類時必須記錄：

```js
research: {
  sourceLabels: ["來源名稱"],
  sourceUrls: ["https://..."],
  checkedAt: "YYYY-MM-DD",
  distributionNote: "採用此海域與條件的理由",
  gameplaySimplification: "為遊戲節奏做過的簡化"
}
```

研究資料可在發行版建置時移除，但專案內需保留，避免後續擴充失去依據。

## 7. 區域與航線資料模型

### 7.1 區域

```js
const REGIONS = [
  {
    id: "first_tide_bay",
    name: "初潮海灣",
    portName: "初潮港",
    currentProfile: "subtropical_warm_current_edge",
    climateTags: ["subtropical", "coastal"],
    spotIds: ["shore", "reef", "deep"],
    unlock: { type: "default" },
    palette: "first_tide",
    musicId: "bay",
    journalPoolId: "first_tide",
    residentSceneIds: [],
    status: "available"
  }
];
```

### 7.2 區域釣點

```js
const REGION_SPOTS = [
  {
    id: "shore",
    regionId: "first_tide_bay",
    name: "近岸淺水區",
    unlock: { type: "default" },
    sceneVariant: "shore",
    habitatTags: ["coastal", "shallow"]
  }
];
```

v0.4 可保留現有釣點 ID，避免存檔與事件資料大規模遷移。未來不同區域若有同名概念，使用全域唯一 ID，例如 `kuroshio_lagoon`。

### 7.3 航線

```js
const ROUTES = [
  {
    id: "first_tide_to_kuroshio",
    fromRegionId: "first_tide_bay",
    toRegionId: "kuroshio_coral_islands",
    name: "玻璃暖流航線",
    currentTags: ["warm_current"],
    unlock: { type: "research", researchId: "first_tide_departure" },
    travelSegments: 3,
    preview: {
      color: "coral_blue",
      silhouetteFishIds: ["unknown_reef_fish_1"],
      musicPreviewId: "kuroshio_hint"
    }
  }
];
```

航線預設為雙向；若故事需要單向首次航程，抵達後必須立即解鎖安全返航，不可把玩家困在新區域。

### 7.4 居民

```js
const RESIDENTS = [
  {
    id: "lighthouse_keeper",
    role: "keeper",
    homeRegionId: "first_tide_bay",
    sceneIds: ["keeper_departure_radio"],
    journalTag: "keeper"
  }
];
```

角色姓名未定時可使用角色型 ID。功能資料與故事文案分離，避免改名影響存檔。

## 8. 世界狀態與存檔

### 8.1 建議新增狀態

```js
world: {
  currentRegionId: "first_tide_bay",
  visitedRegionIds: ["first_tide_bay"],
  unlockedRouteIds: [],
  regionProgress: {
    first_tide_bay: {
      discoveredFishIds: [],
      completedResearchIds: [],
      firstArrivedAt: "ISO-8601"
    }
  },
  travel: null
}
```

航行中：

```js
travel: {
  routeId: "first_tide_to_kuroshio",
  fromRegionId: "first_tide_bay",
  toRegionId: "kuroshio_coral_islands",
  shipId: "drifting_home",
  speedMultiplier: 1,
  segment: 1,
  startedAt: "ISO-8601",
  observations: []
}
```

### 8.2 存檔遷移

v0.4 新增 `world` 時，將 `SAVE_VERSION` 升至 v4：

- v1～v3 存檔載入後預設位於初始海灣。
- 現有發現、漁獲、水族箱、事件、稱號、家具與金幣原樣保留。
- 既有魚的全域釣點條件轉譯成初始海灣棲地，不回寫或重置捕獲紀錄。
- 開發者存檔需解鎖全部「目前已實作」區域與航線；不可預先解鎖只有文件、尚無程式的候選海域。
- 不認得的區域、航線或航行狀態必須安全回到最近有效區域，並保留其他收藏資料。
- 主存檔與備份存檔都需測試 v3 → v4 → 再載入。

### 8.3 v0.5 船隻與航程延伸

- 出航時把目前 `shipId` 與航速倍率寫入該航段，實際時間為航線基礎時間除以倍率。
- 航行中與外海不能切換船隻；讀檔後沿用出航時資料，不因目前目錄調整而跳變。
- 所有航線都能由漂流小屋完成，後期船隻只溫和縮短時間。
- v4→v5 遷移保留目前航程與世界位置，預設船隻為漂流小屋；不回溯補發潮光或歷史日誌。
- 靜潮自動釣架的釣點必須屬於目前停泊港口所在海域，不建立與船位分離的遠端派遣狀態。

## 9. 海圖介面需求

### 9.1 入口

- 第一版將海圖桌放在船屋，避免底部主導航立刻增加第六欄。
- 航行中可從釣魚頁或船屋查看簡化航程卡。
- 後續若世界功能使用頻率足夠，再評估獨立主導航。

### 9.2 海圖畫面資訊層級

1. 目前所在海域與船隻標記。
2. 已解鎖且可直接抵達的相鄰節點。
3. 已到訪海域的完成度與區域魚誌。
4. 未解鎖海域的模糊輪廓、魚影、色彩與解鎖方向。
5. 選中航線的說明、預告與出發按鈕。

### 9.3 防壓力呈現

- 不顯示紅色倒數、燃料不足或錯過警告。
- 未解鎖條件以「再完成一頁觀察，風會帶來新的方向」等正向語句呈現。
- 百分比可用於總覽，但主要回饋應是具體收藏與畫面變化。
- 海圖不塞入每條魚的完整資料；詳細生態回到圖鑑查看。

### 9.4 無障礙

- 地圖節點必須同時具有文字標籤、狀態文字與鍵盤焦點，不只依靠顏色或位置。
- 分支航線在窄螢幕可切換為直向卡片清單。
- 航行狀態需有文字進度；預設動畫本身避免高頻閃爍、快速晃動與長時間大幅視差。
- 音樂預告必須有靜音與文字描述替代。

## 10. 海灣事件的區域化

現有三個事件在 v0.4 加入 `regionIds: ["first_tide_bay"]`，避免玩家位於其他海域時仍顯示海灣事件。

長期事件分三層：

| 層級 | 例子 | 保存方式 |
|---|---|---|
| 區域日事件 | 銀潮靠岸、雨後漂流 | 目前航海日事件＋歷史 |
| 航程觀察 | 暖流漂葉、遠方鯨歌 | 航行中的一次性觀察 |
| 世界自然現象 | 洄游季、長夜星潮 | 多區域可見、永久圖鑑紀錄 |

所有事件維持可重現、無懲罰、非限時營運活動的原則。

## 11. 居民在航線中的使用

### 11.1 燈塔守望者

- 初始海灣提供第一條航線方向與返航意象。
- 玩家遠航後不跨海聯絡；回到眠潮灣時才增加新對話。
- 功能是解釋海況與路徑，並可提供一項簡短的當地居民委託；不建立大量任務清單。

### 11.2 魚市場老闆

- 是不同港口交易與地方紀念物的生活連結。
- 固定留在眠潮灣，不透過遠方合作攤位、信件或熟人網絡延伸任務。
- 各港一般漁獲價格維持固定，不建立價格波動或跨港套利模擬。

### 11.3 生態研究員

- 適合在第一個新海域登場，將區域圖鑑與研究航線自然帶入。
- 固定留在琉光群島，不登船；完成故事後以手繪黑潮生態圖保留記憶。
- 生態資訊以觀察與共同驚喜呈現，不用考題驗證玩家知識。

### 11.4 漂流旅人

- 保留給後續單一海域，固定屬於該地，不作跨航線巡迴角色。
- 以當地短場景、小物與舊航圖線索建立記憶，不使用真實時間窗口。

## 14. 風險與控制

| 風險 | 徵兆 | 控制方式 |
|---|---|---|
| 海圖變成選單換皮 | 抵達前後只有背景不同 | 每區至少綁定魚誌、聲景、收藏物與日誌 |
| 真實生態錯置 | 魚類分布只憑印象 | 保存資料來源與遊戲化簡化說明 |
| 一次設計過多海域 | 所有區域都有名字但沒有可玩內容 | 先完成區域架構與第一趟遠航垂直切片 |
| 存檔遷移破壞收藏 | 現有魚或事件被重設 | 保留全域 fishId，新增包覆層而非重建資料 |
| 航行造成等待壓力 | 玩家被迫停留畫面或定時回來 | 可離線推進、無倒數懲罰、抵達回報一次整理 |
| 分支造成錯過焦慮 | 選一條路永久失去另一區 | 所有主航線最終可解鎖與自由往返 |
| 居民變成任務機器 | 每港大量驚嘆號 | 同時只接受一項當地委託；接受後不過期、不影響故事且可無懲罰放下 |

## 15. 決策狀態

海域順序、第一條航線、風棲港、航程時間、自由返航、手動停泊、區域圖鑑形式與 v0.4 垂直切片均已定案並完成。v0.5 另定案六艘可收藏船隻、出航時鎖定航速，以及只在目前停泊港口運作的靜潮自動釣架；詳細工程契約見 [`V0_5_IMPLEMENTATION_PLAN.md`](versions/v0.5/V0_5_IMPLEMENTATION_PLAN.md)。仍需逐區完成的魚類清單、生態來源與精確內容數值屬製作工作，不再是核心方向問題。
