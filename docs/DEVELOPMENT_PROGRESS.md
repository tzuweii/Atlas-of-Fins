目前程式化美術維持可讀、風格一致與功能辨識。世界擴張前應先完成視聽規格與一個新海域的垂直切片，再決定大量資產產能：

- [x] v0.3 核心內容已完成
- [ ] 至少完成一輪外部遊玩測試
- [ ] 世界海圖、區域圖鑑與船屋成長的資訊層級已驗證
- [ ] 建立魚類比例、朝向、輪廓、光源與動畫模板
- [ ] 建立海域主色、遠景、天氣、環境聲與音樂主題規格
- [ ] 已列出最需要精修的高頻畫面與資產清單

預定優化順序：

1. 魚類與閃光個體辨識度
2. 釣魚過程的水面、咬鉤與收線回饋
3. 船屋與水族箱的層次、光影與裝飾
4. 圖鑑卡片、成就圖示與介面微動效
5. 標題畫面與宣傳用視覺

## 10. 文件維護方式

每次開始新開發項目時：

1. 先在對應設計文件將提案標為已核准，再把項目加入本文件並標記為 `[-]`。
2. 完成實作與測試後才改為 `[x]`，並加入 `TEST_CHECKLIST.md`。
3. 更新「目前驗證狀態」、README 目前功能與最後更新日期。
4. 在「開發紀錄」新增當日完成內容與必要的遷移說明。
5. 若優先級或設計決策改變，保留原因，不只刪除舊項目。
6. 歷史規格保留當時數量；以註記與文件總覽說明現況，不回寫成今日需求。
