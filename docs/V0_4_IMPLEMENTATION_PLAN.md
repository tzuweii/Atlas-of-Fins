## 1. v0.4 完成目標

v0.4 必須證明目前的眠潮灣已成為世界的一部分，而且玩家能完成第一趟真正的遠航：

```text
在眠潮灣整理每日小目標與居民委託
→ 從船屋海圖桌查看琉光群島
→ 沿正式航線出發並可離線推進
→ 抵達風棲港外海後手動停泊
→ 在三個新釣點釣魚並取得區域印章
→ 遇見觀察魚、奇景與澄野
→ 推進琉光群島研究主路
→ 返回眠潮灣並保留全部世界、委託與收藏狀態
```

本版本不是只加入空海圖，也不是一次完成六片海域。完成時需有一條可往返航線、一個內容完整的新海域，以及能繼續擴張至百種以上魚類的資料與資產基礎。

## 3. 每日與居民委託實作契約

### 3.1 每日小目標

- 每個遊戲內航海日固定產生三項，不使用現實日期。
- 生成必須決定性；同一存檔、同一航海日重載後內容不變。
- 只使用已解鎖且能完成的通用條件。
- 已完成但未領取的獎勵在換日前自動入帳。
- 未完成項目換日後直接更新，不保存失敗或中斷紀錄。
- 手動捕獲與手動販售才計數；自動釣魚來源一律忽略。
- 不提供連續天數、補簽、限定收藏、潮光或主線進度。

建議 v4 狀態：

```js
dailyBoard: {
  day: 1,
  entries: [
    {
      instanceId: "1-0-common3",
      templateId: "common3",
      progress: 0,
      goal: 3,
      reward: { type: "coins", amount: 85 },
      claimed: false
    }
  ]
}
```

v3 的 `currentQuests` 必須完整遷移；已完成、已領取與目前進度不得重設。

### 3.2 居民委託

- 居民只在自己的港口提供當日提案。
- 同一時間只允許一項已接受委託。
- 接受後不會換日過期；可完成、回港交付或無懲罰放下。
- 未接受提案可在下一航海日更新；放下後當日不重抽，下一航海日才產生新提案。
- 交付必須發生在正確居民與正確港口，不能遠端領獎。
- 只由手動行為推進，且不得要求未解鎖魚、閃光、最大尺寸、奇景或低機率事件。
- 重複獎勵只使用金幣與通用魚餌。
- 不建立好感、委託等級、連續完成紀錄或主線門檻。

建議 v4 狀態：

```js
residentCommissions: {
  offerDayByResident: {},
  offersByResident: {},
  active: null,
  history: {
    // residentId: { completions: 0, completedTemplateIds: [] }
  }
}
```

`active` 至少保存 `instanceId`、`residentId`、`regionId`、`templateId`、`acceptedDay`、`progress`、`goal`、`reward` 與完成狀態。

### 3.3 統一進度事件

目前的 `updateQuestProgress` 應逐步改成單一純函式入口，讓海灣事件、每日小目標、居民委託與研究共用同一筆手動行為資料：

```js
applyProgressEvent(state, {
  type: "catch",
  source: "manual",
  fishId: "sardine",
  regionId: "sleeping_tide_bay",
  spotId: "shore",
  timeId: "dawn",
  weatherId: "sunny",
  baitId: "bread",
  sizeTier: "normal",
  saleValue: 0
});
```

規則處理不得依賴 DOM。介面只負責送出事件與顯示更新結果，才能以單元測試驗證重複領獎、錯誤來源與存檔遷移。

## 4. 建議模組邊界

為避免一次重寫造成回歸，先保留 `src/data.js`、`src/core.js`、`src/game.js` 作為相容入口，再逐步把新領域移出：

```text
src/
├── data.js                    # 暫時保留的相容匯出
├── core.js                    # 暫時保留的相容匯出
├── game.js                    # 應用啟動與跨畫面協調
├── data/
│   ├── fish.js
│   ├── regions.js
│   ├── routes.js
│   ├── residents.js
│   ├── daily-goals.js
│   └── commissions.js
├── systems/
│   ├── progress-events.js
│   ├── daily-board.js
│   ├── resident-commissions.js
│   ├── world-state.js
│   ├── travel.js
│   ├── observations.js
│   └── research.js
├── persistence/
│   ├── save-schema.js
│   └── migrations.js
└── ui/
    ├── map-view.js
    ├── port-view.js
    ├── daily-board-view.js
    └── resident-view.js
```

拆檔原則：

1. 每次只移動一個領域並保留既有匯出名稱。
2. 搬移前後先跑核心測試，確保不是在同一切片同時搬檔又改規則。
3. 資料檔不直接讀寫存檔；系統函式不直接操作 DOM。
4. UI 不自行重算獎勵、航程或魚池。
5. 全部內容 ID 透過啟動時資料驗證檢查重複與失效引用。
