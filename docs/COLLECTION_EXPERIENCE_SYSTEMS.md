# Atlas of Fins｜收藏體驗系統設計

> 文件狀態：架構參考，尚未實作；正式數值與行為見 [`FINAL_GAME_DESIGN.md`](FINAL_GAME_DESIGN.md)
> 建立日期：2026-07-16
> 正式導入版本：v0.4～v0.5，先完成第一趟遠航垂直切片，再擴充船屋與自動系統
> 涵蓋系統：研究航線、永久探索進度、解鎖預告、船屋成長、自動航行／離線回報、詩意航海日誌、每日小目標與居民委託
> 覆寫規則：潮光、船屋階段、自動釣魚、離線上限、居民、日誌視角與版本順序已由正式定案覆寫

## 1. 系統共同目標

這些系統不是各自獨立的功能清單，而是同一個「幸福感收藏引擎」的不同回饋層：

```text
釣魚與航行產生真實經歷
→ 圖鑑與研究把經歷整理成進度
→ 進度解鎖海域、船屋與居民片段
→ 日誌把變化寫成玩家自己的旅程
→ 剪影、遠景與音樂預告下一個發現
→ 玩家因好奇而再次出航
```

共同原則：

- 不讓玩家因錯過、失敗或暫停遊玩而倒退。
- 不要求閱讀攻略、重置技能或計算最佳路線。
- 每個主要進度都要有可見、可聽或可收藏的回饋。
- 自動系統負責延續陪伴感，不取代主動遊玩的發現效率與情感演出。
- 系統文字保持短、柔和、具體，避免滿畫面任務清單與紅點。

## 2. 研究航線系統

### 2.1 定位

「研究航線」是依海域排列的收藏成長頁。它看起來像一本逐漸補完的觀察冊，而不是需要配點的科技樹。

玩家不需先選擇研究專案；只要正常釣魚、換時段、遇見天氣、完成圖鑑與航行，相關觀察就會自動累積。達成條件後，節點亮起並提供永久獎勵或新內容。

### 2.2 研究頁結構

每個主要海域建議有 3～4 頁，每頁 4～6 個節點：

| 頁別 | 內容 | 典型條件 | 典型獎勵 |
|---|---|---|---|
| 初識 | 第一次理解海域 | 抵達、在不同釣點捕獲、遇見主要天氣 | 區域介紹、日誌紙張、魚影提示 |
| 生態 | 觀察魚群關係 | 發現魚種、熟悉數、不同時段捕獲 | 生態筆記、圖鑑篩選、裝飾 |
| 潮路 | 理解洋流與航行 | 事件、回游魚、居民場景、區域完成度 | 新航線、旗幟、音樂片段 |
| 回望 | 長期精通 | 精通、閃光、紀錄級、完整區域收藏 | 稱號、特殊船帆、日誌終頁 |

主要航線只可綁在「一般玩家不需等待極低機率」的節點；閃光、紀錄級與全精通應放在回望頁或額外星標。

### 2.3 節點類型

- **自動完成節點**：條件達成時直接亮起，適合資訊解鎖與小型紀念。
- **手動翻頁節點**：完成後由玩家點擊展開，提供較大的演出與獎勵，但沒有領取期限。
- **星標觀察**：不阻擋主路線的額外條件，完成後補上星點、短句或裝飾。
- **航線節點**：區域主要成果，解鎖新的目的地或返航捷徑。

不提供可重置分支、排他選擇與研究失敗。

### 2.4 節點條件格式

```js
{
  id: "first_tide_coastal_notes",
  regionId: "first_tide_bay",
  pageId: "first_tide_ecology",
  name: "潮線上的熟面孔",
  description: "在初潮海灣發現 10 種魚。",
  requirements: [
    { type: "region_species", regionId: "first_tide_bay", count: 10 }
  ],
  rewards: [
    { type: "tideglow", amount: 1 },
    { type: "journal_fragment", id: "first_tide_familiar_fins" }
  ],
  nextNodeIds: ["first_tide_current_notes"],
  preview: "一條暖流正把遠方的顏色帶進海灣。"
}
```

條件只讀取目前狀態重新計算；存檔保存完成時間與已觀看演出，避免條件變動後獎勵重複發放。

### 2.5 初始海灣研究頁範例

這是節奏範例，不是核准數值：

| 節點 | 條件 | 回饋 |
|---|---|---|
| 海的第一封信 | 捕獲第一條魚 | 第一頁日誌、1 點永久進度 |
| 三處水色 | 在近岸、礁石、深水各捕獲一次 | 海灣釣點插圖 |
| 從晨霧到星光 | 四時段都有捕獲 | 航海短句、船屋窗飾 |
| 雨落礁邊 | 細雨時在礁石捕獲 | 雨聲日誌背景 |
| 海灣熟面孔 | 發現 10 種魚 | 下一頁與遠方魚影 |
| 鰭之記錄 | 發現 20 種魚 | 觀察旗、暖流線索 |
| 海灣博物學家 | 發現 30 種魚 | 完整頁、遠航節點資格 |
| 玻璃暖流 | 完成一般研究主路 | 第一條遠方航線 |

既有成就與里程碑不應被刪除。研究航線可讀取舊玩家已達成狀態並補亮節點，但同一份金幣或家具獎勵不可重複發放；新獎勵以研究頁、航線與日誌為主。

## 3. 永久探索進度「潮光」

### 3.1 目的

金幣代表日常生活與交易；永久探索進度代表玩家對海洋的理解。兩者分工可以避免高價魚直接買完所有世界內容，也避免增加大量地區代幣。

### 3.2 正式規則

- 全遊戲只有一種永久探索進度，正式名稱為「潮光」。
- 主要來自首次發現、正式觀察魚、圖鑑階級、研究節點、區域研究航線與整區圖鑑。
- 數量小、可預測；玩家能從海圖直接知道距下一航線還差哪些觀察。
- 以永久累積門檻解鎖船屋階段，不實際扣除。
- 航線由區域研究進度解鎖，不要求玩家決定如何花潮光。
- 不可用現實金錢購買、不設每日上限、不因換日或失敗減少。

### 3.3 正式回饋

第一版使用固定獎勵表，不使用複雜公式：

| 行為 | 潮光 |
|---|---:|
| 發現新魚 | 2 |
| 發現正式觀察型魚類 | 4 |
| 魚種達到熟悉 | 1 |
| 魚種達到精通 | 2 |
| 完成研究節點 | 5 |
| 完成區域研究航線 | 10 |
| 完成整區圖鑑 | 15 |

數值仍需以目前 30 種魚的真實存檔驗證節奏，但調整時不得改成可消費貨幣或航線配點。

## 4. 下一個解鎖預告

### 4.1 目的

玩家持續遊玩的主要原因應是「想看下一個東西」，而不是「還差 17%」。所有收藏介面都要提供柔和但具體的下一步。

### 4.2 預告層級

| 進度距離 | 顯示內容 |
|---|---|
| 遙遠 | 海域主色、氣候短句、模糊地形 |
| 接近 | 1～2 個魚類剪影、港口輪廓、居民外觀或器物剪影 |
| 即將解鎖 | 名稱片段、短音樂預覽、明確剩餘條件 |
| 已解鎖 | 完整名稱、出航演出與第一個新目標 |

### 4.3 規則

- 預告不可洩漏全部魚名與完整地圖，保留發現感。
- 不把進度藏在詩句裡；詩意提示旁仍要有清楚條件。
- 音樂預覽短且可關閉，不能自動高音量播放。
- 色盲或靜音玩家仍可透過文字、輪廓與狀態理解。
- 解鎖動畫預設避免高頻閃爍與快速鏡頭移動；不另提供低動態模式。

## 5. 船屋成長系統

### 5.1 定位

船屋是玩家最長期、最具情感的收藏畫面。每次遠航帶回的魚、旗幟、照片、器物與聲音都應留下痕跡，使玩家不需要讀數字也能看出旅程進度。

### 5.2 空間層級

沿用固定區域而非自由建造：

- 睡眠區：床鋪、毛毯、旅行紀念。
- 觀察區：水族箱、圖鑑、研究桌。
- 海圖區：世界航線與收音機。
- 生活區：桌面、茶具、書架與照片。
- 甲板／外觀：船帆、旗幟、燈、船體細節與港口紀念物。

現有 5 種家具插槽與固定水族箱可逐步映射到這些區域，不需一次重做自由布置。

### 5.3 正式成長階段

| 潮光 | 階段 | 可見變化 |
|---:|---|---|
| 0 | 漂流小屋 | 基礎床位、桌面與水族箱 |
| 20 | 潮聲居所 | 加大舷窗、照片牆、觀察架與自動釣架圖紙 |
| 50 | 遠航書房 | 航圖桌、日誌書架與第二展示牆 |
| 90 | 微光水室 | 大型水族景窗與區域生態光影 |
| 140 | 世界船屋 | 外部觀景甲板、航線旗幟與居民紀念品 |
| 200 | 星潮博物艙 | 多海域收藏廊與完整世界展示空間 |

資產量仍需依高畫質產能驗證，但階段名稱、順序與潮光門檻已定案。

### 5.4 升級規則

- 主要船屋階段由世界收藏自然解鎖，不要求一次支付大量金幣。
- 一般家具仍可用金幣購買，作為持續販售魚類的生活循環。
- 區域紀念物由首次抵達、研究頁或居民場景取得，不設隨機箱。
- 家具提供氛圍或便利性，不提高稀有魚機率等必備戰力。
- 船屋變化在釣魚主場景或甲板輪廓也應可見，避免只存在於室內面板。

### 5.5 居民紀念

- 居民固定留在所屬海域，不登船或跨海聯絡。
- 完成角色故事後，以手繪圖、照片、器物與日誌頁留在船屋。
- 不加入送禮條、好感數值與每日互動獎勵。

## 6. 自動航行與放置型釣魚

### 6.1 定位

自動系統用來維持「船仍在海上生活」的感覺，服務短時間回訪與收藏累積。它不能比主動釣魚更擅長發現稀有內容，也不能變成要求玩家定時收菜的工作。

### 6.2 分階段導入

1. **航行回報**：選定航線後，抵達時整理沿途被動觀察與航海日誌，不帶回自動漁獲。
2. **靜潮自動釣架**：以金幣購買設備，在已造訪釣點取得已發現一般魚與熟悉度，不觸發新收藏或事件目標。
3. **離線旅程回報**：關閉遊戲後依安全上限產生摘要；不精確模擬每秒世界狀態。

v0.4 先實作離線航程與抵達回報；v0.5 再加入獨立的靜潮自動釣架與離線釣魚結算。

### 6.3 主動與自動的分工

| 項目 | 主動釣魚 | 自動／離線 |
|---|---|---|
| 已發現的一般捕獲型魚與金幣 | 基準效率 | 約手動 50% |
| 新魚首次發現 | 正常 | 不可 |
| 觀察魚、奇景與敏感放流魚 | 依各自流程記錄 | 不捕獲 |
| 閃光與紀錄級 | 正常判定 | 不判定閃光；可更新一般尺寸 |
| 事件特殊目標 | 正常累積 | 不自動完成 |
| 熟悉度 | 完整累積 | 可有限累積 |
| 情感演出與日誌 | 完整 | 產生簡短回報，首次內容留給主動觀看 |

自動系統不提供魚影線索；新發現與驚喜完整保留給主動遊玩。

### 6.4 離線回報規則

- 離線時間上限正式定為 3 小時；目的為避免放置效率高於主動遊玩，不做催促倒數。
- 未滿最短時間仍可顯示一句環境變化，不一定產生物品。
- 回報以一份簡潔摘要呈現，不逐條播放數十次捕獲動畫。
- 漁獲箱無容量上限的既有原則可保留，但自動結果需要單次數量上限。
- 裝置時間倒退、極端跳時或存檔缺欄位時，回報歸零或使用安全上限，不能破壞存檔。
- 自動釣架需要魚餌，魚餌耗盡時自動停止；晚領取不會失去成果。

### 6.5 自動狀態資料草案

```js
idleVoyage: {
  enabled: true,
  regionId: "first_tide_bay",
  spotId: "shore",
  startedAt: "ISO-8601",
  lastResolvedAt: "ISO-8601",
  mode: "observe", // "observe" | "fish"
  seed: "deterministic-seed"
}
```

回報應可決定性重算或保存已結算結果，避免重載重複領取。

## 7. 詩意航海日誌

### 7.1 定位

日誌是玩家旅程的情感圖鑑。它不只列出「捕獲 3 條魚」，而是把真實世界狀態轉成短而可信的觀察，使每位玩家的頁面因行程與收藏順序略有不同。

### 7.2 生成來源

一則日誌可讀取：

- 航海日與遊戲內時段。
- 目前海域、釣點、天氣與海灣事件。
- 首次發現、紀錄級、閃光、精通或一般漁獲。
- 新解鎖研究頁、船屋階段、家具或航線。
- 玩家在居民所屬海域發生的相遇、後續片段與共同觀察。
- 航行出發、沿途現象、抵達與返航。
- 水族箱目前展示的代表魚或玩家裝備稱號。

### 7.3 模組化句庫

```js
const JOURNAL_TEMPLATES = [
  {
    id: "first_discovery_rain_reef",
    trigger: "first_discovery",
    conditions: {
      weatherIds: ["rain"],
      habitatTags: ["reef"]
    },
    fragments: {
      opening: ["細雨把礁石的邊緣磨得很安靜。"],
      subject: ["{fishName} 從漂流的海草下露出一道光。"],
      closing: ["今晚，圖鑑裡多了一頁潮濕的顏色。"]
    },
    cooldownDays: 3
  }
];
```

生成流程：

```text
遊戲事件發生
→ 找出符合地點／時間／天氣／事件類型的模板
→ 排除近期重複與已超過使用上限的句群
→ 以保存的 seed 選擇片段
→ 填入魚名、港口、角色與收藏狀態
→ 保存生成後的完整文字與來源資料
```

日誌一旦生成就保存完整文字，不因日後模板更新而改寫玩家舊回憶。

### 7.4 日誌類型

| 類型 | 長度 | 觸發 | 是否唯一 |
|---|---:|---|---|
| 航海短記 | 1～3 句 | 有意義的首次發現或世界變化 | 可重複模板但需冷卻 |
| 初遇頁 | 2～4 句 | 新魚、新港口、新居民 | 每項一次 |
| 航程頁 | 3～5 句 | 出航、沿途、抵達 | 每次航程一頁 |
| 研究頁 | 2～4 句 | 完成主要研究節點 | 每節點一次 |
| 居民頁 | 3～5 句 | 角色場景 | 每場景一次，可回看 |
| 回望頁 | 4～6 句 | 完成區域或世界收藏 | 每里程碑一次 |

### 7.5 語氣規格

- 使用繁體中文與玩家第一人稱「我」，短句為主，每則聚焦一個感官意象。
- 優先寫玩家實際看見的天氣、光、聲音、魚與船屋物件。
- 避免假裝玩家有未發生的情緒或行為，例如「我哭了」「我決定永不回頭」。
- 避免過度華麗、每句比喻、神祕預言與重複的「彷彿」。
- 真實魚類生態描述需正確；詩意不能改寫成錯誤科普。
- 居民台詞保持角色口吻，但不寫成長篇小說。
- 同一關鍵片語需有冷卻或使用上限，避免日誌看起來像隨機拼貼。

### 7.6 日誌資料模型

```js
journalEntries: [
  {
    id: "journal-uuid",
    type: "first_discovery",
    day: 12,
    createdAt: "ISO-8601",
    regionId: "first_tide_bay",
    templateId: "first_discovery_rain_reef",
    text: "已完成組合的文字",
    refs: {
      fishIds: ["yellow_boxfish"],
      residentIds: [],
      eventId: "rain_drift"
    },
    isRead: false
  }
]
```

需設定保存上限或分層聚合：唯一收藏頁永久保存；一般今日潮記可保留最近固定數量，舊頁以航海週／區域摘要封存，避免 localStorage 無限增長。

### 7.7 介面

- 船屋書架或桌面是主要入口，不立即增加底部導航。
- 首頁顯示最近一頁與「這趟旅程新增幾頁」，不顯示急迫紅點。
- 可依海域、魚類、居民與航海日篩選。
- 圖鑑魚種詳細頁可跳到提及該魚的日誌。
- 世界海圖的區域節點可顯示該區日誌冊完成情形。
- 日誌完全唯讀，不提供修改、刪除、加註、收藏標記或手動指定展示頁。

## 8. 系統整合優先順序

依賴關係如下：

```text
世界區域資料與目前位置
├── 區域研究航線
│   ├── 永久探索進度
│   └── 航線解鎖預告
├── 船屋海圖桌與區域紀念物
├── 航行狀態
│   └── 航行／離線回報
└── 統一遊戲事件紀錄
    └── 詩意航海日誌
```

因此正式順序為：

1. v0.4 完成區域、航線、存檔、高畫質產線與琉光群島第一趟遠航垂直切片。
2. 同一切片以琉光群島驗證區域魚誌、觀察魚、澄野與研究主路。
3. v0.5 加入潮光、船屋前兩次成長、動態舷窗與解鎖預告。
4. 建立統一事件紀錄並生成第一人稱唯讀航海日誌。
5. 加入靜潮自動釣架與 3 小時離線回報，再以手動 50% 效率進行平衡驗證。

## 9. 驗收原則草案

### 9.1 研究航線

- [ ] 正常釣魚即可推進主路，不需要手動選研究或查看攻略。
- [ ] 舊存檔能補亮已達成節點，且既有獎勵不會重複發放。
- [ ] 閃光、紀錄級與全精通不阻塞主要海域解鎖。
- [ ] 每個主要節點有具體獎勵與下一步預告。

### 9.2 船屋

- [ ] 升級前後能從主場景看出至少一項輪廓、光線或物件差異。
- [ ] 水族箱、家具與新區域紀念物可共存，舊收藏不遺失。
- [ ] 沒有必須購買的戰力家具或高壓資源維護。

### 9.3 自動／離線

- [ ] 同一段離線狀態只能結算一次，重載不重複領取。
- [ ] 時鐘異常與長時間離線使用安全上限，不破壞存檔。
- [ ] 自動結果只包含已發現的一般捕獲型魚，不取得新魚、閃光、觀察魚、奇景或敏感放流魚，也不完成事件主目標。
- [ ] 主動釣魚在新發現、稀有收藏與效率上保持明確優勢。
- [ ] 即使不啟用自動釣架，玩家仍可正常推進全部主要內容。

### 9.4 日誌

- [ ] 文字中的海域、魚、天氣、時段、事件與角色均來自真實遊戲狀態。
- [ ] 同一頁保存後不因模板更新而改寫。
- [ ] 近期句型不明顯重複，且不產生空欄位或不存在的名稱。
- [ ] 唯一頁永久保存，一般頁有可預測的封存／上限規則。
- [ ] 舊存檔沒有歷史日誌時能從當下開始，不偽造過去事件。

## 10. 風險與控制

| 風險 | 控制方式 |
|---|---|
| 研究航線成為換皮任務表 | 節點少而有畫面變化；條件自動累積；不設每日刷新 |
| 潮光變成第二種金幣 | 使用累積門檻、不反覆消耗、不販售、不指數膨脹 |
| 船屋只增加圖示 | 每個主要階段至少改變輪廓、光影、聲音或生活動作 |
| 自動收益取代釣魚 | 不自動首發現／傳說魚／事件目標，主動效率明顯較高 |
| 離線系統催促登入 | 無滿倉損失警告、無領取倒數、可停用、回報有安全上限 |
| 日誌像隨機句子 | 使用狀態條件、人工句庫、冷卻、保存完成文字與人工 QA |
| localStorage 持續膨脹 | 聚合一般日誌、唯一頁永久保存、設定資料上限與遷移測試 |
| 舊玩家一次跳過全部體驗 | 補登進度但把主要演出整理成可逐頁觀看，不重發既有資源 |

## 11. 決策狀態

研究航線、潮光、船屋階段、自動釣架、3 小時離線上限、手動 50% 效率與第一人稱唯讀日誌均已定案。每日小目標與居民委託正式保留，但只依遊戲內航海日運作，且不得加入連續登入、過期懲罰或限定收藏。一般日誌的實際保存數量與封存資料量仍需以瀏覽器儲存測試決定。

## 12. 每日小目標與居民委託補充

### 12.1 每日小目標

- 沿用 v0.3 每個航海日三項目標的輕量形式，並改為資料驅動、跨海域合法條件生成。
- 已完成但未領取的普通獎勵在換日前自動入帳；未完成目標換日後直接更新，沒有失敗紀錄。
- 不計現實日期、連續天數或補簽，也不提供限定收藏、潮光或主線進度。
- 自動釣魚不推進每日目標；同一次手動行為可同時推進事件、研究與委託。

### 12.2 居民委託

- 居民只在所屬港口提出委託，同時只保留一項已接受委託。
- 接受後永久保留到完成或玩家主動放下；完成後回到原居民處交付。
- 條件從已解鎖的一般內容生成，不要求閃光、奇景、最大尺寸或低機率事件。
- 重複獎勵只給金幣或通用魚餌，不建立好感、委託等級或能力加成。
- 開發者模式需能產生、接受、完成、交付、放下與重置委託。
