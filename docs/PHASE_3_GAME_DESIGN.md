# Atlas of Fins｜第三階段遊戲設計規格

> 版本定位：v0.3.0-alpha.3「海灣事件與特殊目標」
> 文件狀態：Slice A、B、C 已完成
> 本階段重點：讓不同航海日具有可辨認的魚池變化與短期收藏目標
> 已完成事件：銀潮靠岸、月光潮汐、雨後漂流

## 1. 設計目標

v0.3 不先增加大量魚種，而是利用既有釣點、時段、天氣與魚池資料，讓玩家在每個航海日開始時多一個「今天想去哪裡、想找什麼」的理由。

事件系統遵守以下原則：

- 事件是機會，不是期限壓力；錯過不扣除資源，也不破壞收藏進度。
- 同一航海日的事件必須可以重現，方便存檔、讀檔與自動測試。
- 事件先改變魚池權重與短期目標，不直接改寫張力小遊戲。
- 首次完成提供永久收藏獎勵，重複完成提供一般資源。
- 平靜日也是節奏的一部分，不保證每天都有事件。

核心循環延伸為：

```text
查看今日海灣事件
→ 依事件選擇釣點與目標魚
→ 捕獲目標並推進分階段提示
→ 完成特殊目標
→ 取得首次收藏獎勵或重複獎勵
→ 睡眠推進到下一個航海日並產生可重現的新事件
```

## 2. Slice A｜銀潮靠岸

### 2.1 出現規則

- 第 1 日必定出現，之後依事件資料表輪替，於第 7、13 日再次出現。
- 偶數航海日為平靜日。
- 排程只依 `day` 與事件資料表計算，不使用不可重現的即時亂數。
- 事件持續整個航海日，睡眠回到清晨並增加航海日時才換日。

### 2.2 世界效果

| 欄位 | 設定 |
|---|---|
| 事件 | 銀潮靠岸 |
| 主要釣點 | 近岸淺水區 |
| 加成魚種 | 沙丁魚、鯷魚 |
| 魚池權重 | 目標魚 `×4` |
| 其他魚種 | 維持原本權重 |

事件只調整候選魚權重，不保證下一竿必定是目標魚。

### 2.3 特殊目標

在事件當日的近岸淺水區捕獲 3 條沙丁魚或鯷魚。進度只計算成功捕獲，不計算拋竿、咬鉤或逃脫。

分階段提示：

| 進度 | 提示 |
|---:|---|
| 0 / 3 | 銀色水紋剛靠近淺灘，麵包糰會是舒服的起點。 |
| 1 / 3 | 第一束銀光已寫進日誌，再沿著近岸找找。 |
| 2 / 3 | 魚群正在船邊轉向，再一次相遇就能完成觀察。 |
| 3 / 3 | 今日銀潮觀察完成。 |

### 2.4 獎勵

- 首次完成：永久稱號「銀潮見證者」。
- 後續航海日再次完成：60 金幣。
- 獎勵於達成時自動發放，事件卡與捕獲結果必須顯示完成狀態。

## 3. Slice B｜月光潮汐

### 3.1 出現規則

- 第 3 日首次出現，之後每六個航海日再次輪替。
- 事件存在整個航海日，但魚池倍率與目標只在夜晚生效。
- 清晨、白天與黃昏顯示等待提示，不會暗中提高魚池權重或累積進度。
- 開發者模式以第 99 日夜晚進入，可直接驗證事件內容。

### 3.2 世界效果

| 欄位 | 設定 |
|---|---|
| 事件 | 月光潮汐 |
| 生效時段 | 夜晚 |
| 生效釣點 | 礁石邊緣、海灣深水區 |
| 加成魚種 | 小管、白帶魚幼魚、燈籠魚 |
| 魚池權重 | 目標魚 `×3.5` |
| 其他條件 | 維持原本天氣、魚餌與魚竿規則 |

礁石區保留小管作為早期可達成目標；已取得強化遠投竿的玩家可前往深水尋找全部三種月光訪客。

### 3.3 特殊目標

事件當日夜晚，在礁石或深水捕獲 2 條小管、白帶魚幼魚或燈籠魚。

| 進度 | 提示 |
|---:|---|
| 等待夜晚 | 月色尚未升起，先回船屋休息並準備小蝦或發光魚餌。 |
| 0 / 2 | 礁石可尋找小管，深水還有更多夜行身影。 |
| 1 / 2 | 第一位月光訪客已留下紀錄，再沿著冷色潮光尋找一次。 |
| 2 / 2 | 今日月光潮汐觀察完成。 |

### 3.4 獎勵

- 首次完成：永久稱號「月潮聆聽者」。
- 後續航海日再次完成：80 金幣。
- 獎勵沿用 Slice A 的自動發放與事件歷史，不增加新的存檔版本。

## 4. Slice C｜雨後漂流

### 4.1 出現規則

- 第 5 日首次出現，之後每六個航海日再次輪替。
- 事件產生時將當日天氣固定為細雨，確保目標可執行且畫面與魚池一致。
- alpha.1／alpha.2 已保存的當日事件實例仍優先保留，不因新輪替被覆寫。

### 4.2 世界效果

| 欄位 | 設定 |
|---|---|
| 事件 | 雨後漂流 |
| 生效天氣 | 細雨 |
| 生效釣點 | 礁石邊緣 |
| 加成魚種 | 黑鯛、石狗公、花枝、海鰻 |
| 魚池權重 | 目標魚 `×3.2` |
| 推薦魚餌 | 小蝦、沙蠶 |

### 4.3 特殊目標

事件當日細雨時，在礁石捕獲 2 條黑鯛、石狗公、花枝或海鰻。

| 進度 | 提示 |
|---:|---|
| 0 / 2 | 沿著浮木與海草交界拋竿，小蝦或沙蠶容易吸引躲藏其中的魚。 |
| 1 / 2 | 第一份雨潮紀錄已完成，漂流帶裡還有另一道身影。 |
| 2 / 2 | 今日雨後漂流觀察完成。 |

### 4.4 獎勵

- 首次完成：永久稱號「雨潮守望者」。
- 後續航海日再次完成：90 金幣。
- 獎勵與完成歷史沿用 v3 資料模型。

## 5. 資料模型

```js
state.bayEvent = {
  instanceId: "1-silver_tide",
  eventId: "silver_tide",
  day: 1,
  progress: 0,
  completedAt: null,
  rewardLabel: null
};

state.bayEventHistory = {
  silver_tide: {
    completions: 1,
    firstCompletedAt: "ISO-8601",
    lastCompletedDay: 1
  }
};
```

- `bayEvent` 保存目前航海日的事件實例與進度。
- `bayEventHistory` 保存永久完成次數，用來判定首次或重複獎勵。
- 事件定義以 `spotIds` 支援多釣點，以選填的 `timeIds`、`weatherIds` 支援限定時段與天氣。
- `forceWeather` 可讓事件生成時同步世界天氣；目前只用於雨後漂流。
- 存檔格式升級至 v3；v1／v2 存檔載入時保留全部既有資料，並依目前航海日建立事件狀態。
- v0.3.0-alpha.1／alpha.2 已存在的當日事件實例會優先保留，不因後續版本的新輪替而重設進度。
- 不認得的事件 ID、負數進度與損壞歷史資料必須安全忽略或修正。

## 6. 介面需求

- 釣魚畫面的右側欄顯示今日事件卡，包含事件名稱、效果、目標、進度、分階段提示與獎勵。
- 平靜日顯示簡短海況卡，不以空白或錯誤狀態呈現。
- 世界場景標示目前事件名稱。
- 捕獲目標魚後，捕獲結果顯示事件進度；完成時顯示實際取得的獎勵。
- 限定時段或天氣事件必須明確區分「等待條件」與「目前生效」，並提供準備提示。
- 桌面與手機寬度都必須可閱讀，不增加新的主導航頁籤。

## 10. 事件內容基礎完成後

三個預定的具名事件已完成。後續工作屬於事件系統深化，而不是本輪新增事件：

1. 多階段事件鏈：先觀察海況，再完成指定條件捕獲。
2. 事件收藏頁：記錄曾遇過、完成過與首次完成日期。

新增內容前先觀察玩家是否會因事件主動改變釣點、魚餌或遊玩時段；若玩家只把事件視為額外金幣來源，應先改善收藏獎勵與事件敘事回饋。
