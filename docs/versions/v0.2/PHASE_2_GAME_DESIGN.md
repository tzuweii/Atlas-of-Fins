# Atlas of Fins｜第二階段遊戲設計規格

> 版本定位：v0.2「收藏航程」
> 文件狀態：已完成規格與驗收紀錄
> 實作進度：Slice A、B、C、D 已完成
> 本階段重點：深化既有內容，不進行全面美術翻修
> 核心功能：圖鑑熟悉度、閃光個體、收藏成就、船屋水族箱

本文件保存 v0.2 當時以 20 種魚、10 格水族箱與 12 項成就為範圍的設計。v0.3.0-alpha.4 已將收藏延伸至 30 種魚、15 格水族箱與 13 項成就；現況以 [`DEVELOPMENT_PROGRESS.md`](../../CURRENT.md) 為準。

## 1. 設計目標

第二階段不以增加大量魚種為主，而是讓現有 20 種魚在首次捕獲之後仍然值得反覆尋找。

本階段要改善三個問題：

1. 玩家發現一種魚並捕獲三次後，繼續捕獲同種魚的收藏價值不足。
2. 漁獲目前只有出售一種主要用途，缺乏「留下這一條」的情感選擇。
3. 船屋雖然可以布置，卻還沒有直接展示玩家釣魚成果的空間。

完成後的延伸循環為：

```text
選擇目標魚
→ 依地點／時間／天氣準備
→ 捕獲並判定尺寸、紀錄與閃光個體
→ 更新圖鑑熟悉度與成就
→ 選擇出售、保留或放入水族箱
→ 在船屋查看收藏
→ 為下一個圖鑑目標再次出航
```

### 1.1 設計原則

- **每次捕獲都有意義**：即使沒有刷新紀錄，也會累積該魚種的熟悉度。
- **驚喜而非壓力**：閃光個體是長期驚喜，不設限時、連續登入或錯過懲罰。
- **收藏不綁戰力**：水族箱與成就以展示和進度為主，不提供必須維持的數值增益。
- **舊存檔可延續**：現有發現數、捕獲數、最佳長度與重量全部保留。
- **低美術依賴**：先以現有 SVG、色彩變體、徽記與文字完成系統驗證。

### 1.2 成功指標

內部遊玩測試應達到：

- 玩家在發現 10 種魚之後，仍能說出至少兩個想繼續釣魚的明確目標。
- 捕獲結果畫面能在 2 秒內讓玩家辨認「新魚、刷新紀錄、閃光個體、熟悉度提升」。
- 玩家不需說明即可完成一次「漁獲箱 → 水族箱 → 取回」流程。
- 舊存檔載入後不遺失現有進度，且可正常產生新格式漁獲。
- 一般玩家約 4～6 小時可達成 10 種魚的「熟悉」階級，但不預期在此時間內完成全部精通。

## 2. 版本範圍

### 2.1 本階段必做

- 圖鑑熟悉度四階段
- 捕獲履歷資料補充
- 單一類型的閃光個體
- 閃光個體保底機制
- 收藏成就與一次性獎勵
- 船屋水族箱解鎖、放入、取回與換位
- 捕獲結果、圖鑑、漁獲箱、船屋的必要 UI
- 存檔版本升級與遷移
- 核心邏輯單元測試與瀏覽器流程測試

### 2.2 本階段不做

- 新海域與新魚種
- 魚類繁殖、餵食、死亡或水質管理
- 水族箱離線收益
- 家具自由拖曳或多樓層船屋
- 多種特殊外觀、基因或詞綴系統
- 全面替換現有魚類插圖與場景美術
- 排行榜、社交分享、雲端帳號

## 3. 圖鑑熟悉度

### 3.1 階級

沿用現有 `discovered[fishId].count`，不新增需要玩家理解的經驗值。

| 階級 | 捕獲次數 | 名稱 | 解鎖內容 |
|---|---:|---|---|
| 0 | 0 | 未發現 | 剪影、未知名稱、模糊地點提示 |
| 1 | 1 | 初次相遇 | 名稱、插圖、簡介、首次捕獲日期、最佳紀錄 |
| 2 | 3 | 生態筆記 | 詳細介紹、偏好魚餌、活躍時段、有趣知識 |
| 3 | 5 | 熟悉 | 捕獲地點／時間／天氣分布、熟悉徽記 |
| 4 | 10 | 精通 | 精通徽記、該魚種閃光保底門檻降低 |

原本三次捕獲解鎖完整生態文字的節奏保持不變。新增的 5 次與 10 次目標提供長期追求，但不阻擋既有資訊。

### 3.2 精通效果

精通不是直接提高金幣或釣魚能力，而是改善收藏體驗：

- 該魚種的閃光保底由連續 30 次未出現，降低為連續 20 次未出現。
- 圖鑑卡片顯示精通徽記。
- 解鎖該魚種的「航海短句」一則，作為長期收藏文字。

每種魚的航海短句屬於後續內容填寫工作；若文字尚未完成，系統功能不應被阻擋。

### 3.3 捕獲履歷

每種魚的圖鑑新增以下統計：

- 捕獲總數
- 最長與最重紀錄
- 首次捕獲日期
- 最近捕獲日期
- 曾捕獲地點
- 曾捕獲時段
- 曾捕獲天氣
- 是否捕獲過閃光個體

不保存無上限的完整歷史清單；圖鑑只保存聚合資料，避免存檔持續膨脹。實際仍持有的漁獲與水族箱魚隻保留完整捕獲資訊。

## 4. 閃光個體

### 4.1 定位

「閃光個體」是同種魚的罕見外觀變體，是第二階段唯一的特殊個體類型。它不算新的圖鑑魚種，不影響 20 種魚的完成率。

第一版視覺可使用：

- 現有 SVG 的高亮配色
- 魚身輕微光點或外框
- 漁獲卡片的閃光徽記
- 捕獲結果的短促金色粒子

之後進行美術升級時，可以為各魚種替換成獨立特殊配色。

### 4.2 出現機率

每次成功捕獲後才判定閃光，避免改變魚種候選池與咬鉤節奏。

基礎機率：

| 條件 | 閃光機率 |
|---|---:|
| 一般捕獲 | 2% |
| 紀錄級尺寸 | 額外 +2% |
| 該魚種已精通 | 額外 +1% |
| 連續未出現保底 | 100% |

最終機率上限為 5%。

### 4.3 保底規則

- 每個魚種各自記錄 `shimmerPity`。
- 捕獲非閃光個體時加 1，捕獲閃光個體時歸零。
- 未精通魚種：第 30 次必定閃光。
- 已精通魚種：第 20 次必定閃光。
- 舊存檔遷移時從 0 開始，不回溯既有捕獲次數。

採用分魚種保底，是為了讓玩家能明確追求喜歡的魚，而不被其他常見魚消耗保底。

### 4.4 價格與收藏

- 閃光個體售價倍率：`×2`。
- 售價在捕獲時固定，後續版本調整倍率不回算既有漁獲。
- 第一次捕獲某魚種的閃光個體時，獲得 75 金幣研究獎勵。
- 閃光個體可以出售、保留或放入水族箱。
- 圖鑑會永久記錄曾經捕獲過閃光個體，因此出售不會抹除收藏紀錄。

### 4.5 判定順序

```text
選出魚種
→ 生成長度與重量
→ 判定尺寸階級
→ 判定閃光
→ 計算售價
→ 寫入捕獲環境資料
→ 更新圖鑑、保底、成就與委託
```

## 5. 船屋水族箱

### 5.1 解鎖節奏

水族箱作為圖鑑收藏與船屋生活的連接點。

| 發現魚種 | 水族箱狀態 | 容量 |
|---:|---|---:|
| 0～4 | 尚未解鎖，顯示鎖定提示 | 0 |
| 5 | 解鎖「海灣觀察箱」 | 3 |
| 10 | 第一次擴建 | 5 |
| 15 | 第二次擴建 | 8 |
| 20 | 完成型展示箱 | 10 |

解鎖與擴建不收取金幣，直接跟隨圖鑑里程碑。原因是水族箱是收藏核心功能，不應因玩家把錢花在魚竿或魚餌上而延後使用。

### 5.2 放入與取回

- 玩家只能把目前漁獲箱內的魚放入水族箱。
- 放入後，魚從 `catchInventory` 移至 `aquarium.fish`，不能同時出售。
- 玩家可隨時免費取回，魚會回到漁獲箱。
- 水族箱已滿時，玩家必須先取回一條或使用「替換」操作。
- 替換操作必須顯示即將取回與放入的魚，不使用破壞性確認文字。
- 水族箱魚隻不會死亡、不需餵食、不消耗道具。

### 5.3 排列

- 使用固定展示槽，支援左右換位。
- 不做自由拖曳位置與水深配置。
- 每個槽位保存一個漁獲 `uid` 對應的完整標本資料。
- 同種魚可以重複展示，讓玩家能並列一般、閃光與紀錄個體。

### 5.4 船屋呈現

船屋新增「海灣觀察箱」區塊：

- 顯示目前展示數與容量。
- 顯示各魚的名稱、尺寸、閃光與紀錄標籤。
- 點選魚隻開啟標本卡，可查看捕獲日期、地點、時段、天氣、魚餌。
- 空槽提供「從漁獲箱選擇」操作。
- 未解鎖時顯示「發現 5 種魚後，船屋將加入一座小型觀察箱」。

水族箱第一版不取代現有五個家具插槽，應作為船屋固定設施，避免與睡眠、牆面、桌面、燈光和角落家具競爭位置。

### 5.5 展示原則

- 水族箱不提供金幣產出、魚池加成或稀有率提升。
- 玩家選擇展示的依據應是喜愛、故事與紀錄，而不是最佳配置。
- 展示中的魚仍計入持有魚隻，但不計入可販售總價。

## 6. 收藏成就

### 6.1 成就形式

- 成就為永久、一次性、無期限目標。
- 達成時自動完成，獎勵需由成就面板手動領取。
- 未領取獎勵顯示於主導航，不以每日紅點或倒數製造壓力。
- 第一版獎勵以金幣、稱號與水族箱裝飾標記為主，不新增戰力。

### 6.2 首批成就

| ID | 名稱 | 條件 | 獎勵 |
|---|---|---|---|
| `first_catch` | 海的第一封信 | 捕獲第一條魚 | 40 金幣 |
| `species_5` | 海灣初識 | 發現 5 種魚 | 稱號「海灣訪客」 |
| `species_10` | 潮汐觀察家 | 發現 10 種魚 | 120 金幣 |
| `species_20` | 鰭之圖鑑 | 發現全部 20 種魚 | 稱號「鰭之記錄者」 |
| `familiar_5` | 熟悉的身影 | 5 種魚達到熟悉 | 120 金幣 |
| `mastery_1` | 一種魚，一片海 | 任一魚種達到精通 | 稱號「耐心觀察者」 |
| `mastery_10` | 海灣研究者 | 10 種魚達到精通 | 240 金幣 |
| `record_3` | 尺寸之外 | 捕獲 3 條紀錄級魚 | 100 金幣 |
| `shimmer_1` | 波光留下來了 | 首次捕獲閃光個體 | 水族箱光點標記 |
| `shimmer_5` | 收集海上的星星 | 捕獲 5 種不同閃光魚 | 稱號「拾光者」 |
| `aquarium_3` | 小小海灣 | 水族箱同時展示 3 條魚 | 80 金幣 |
| `conditions_4` | 從晨霧到星光 | 四個時段都曾成功捕獲魚 | 80 金幣 |

現有圖鑑里程碑與成就可以同時存在：里程碑負責主要功能解鎖，成就負責橫向收藏目標。若條件相同，不重複發放既有家具。

### 6.3 稱號

第一版稱號只顯示在成就面板與存檔摘要，不提供能力加成。玩家可選擇一個已解鎖稱號裝備；未選擇時顯示「海灣旅人」。

## 7. 玩家流程與介面資訊

### 7.1 捕獲結果

資訊優先順序：

1. 閃光個體或首次發現
2. 魚名
3. 長度、重量、售價
4. 最長／最重紀錄
5. 熟悉度進度
6. 操作：查看圖鑑、收入漁獲箱

同一次捕獲可能同時觸發多個狀態。主標籤只顯示優先級最高者，其餘以次要徽記呈現，避免畫面同時出現過多彩帶。

範例：

```text
✦ 閃光個體
黑鯛
37.2 cm｜1.48 kg｜389 金幣
最長紀錄 · 熟悉度 4 / 5
```

### 7.2 圖鑑

圖鑑卡片新增：

- 熟悉度階級或進度
- 是否曾捕獲閃光個體
- 精通徽記

詳細頁新增：

- `捕獲次數 / 下一階級需求`
- 首次與最近捕獲日期
- 已記錄的地點、時段、天氣
- 閃光個體紀錄
- 「查看持有標本」篩選入口

### 7.3 漁獲箱

新增篩選與排序：

- 全部／閃光／紀錄級／水族箱可用
- 最近捕獲／售價／長度／重量

每張漁獲卡新增「放入水族箱」。水族箱未解鎖或已滿時，按鈕應顯示原因，不可靜默失效。

### 7.4 船屋

船屋的操作順序維持：

1. 水族箱收藏
2. 休息切換時段
3. 家具布置
4. 圖鑑里程碑

水族箱是新增的主要內容，但不應遮蔽原有床鋪與家具操作。

### 7.5 成就入口

第一版不增加第六個底部導航按鈕。成就入口放在圖鑑標題區，圖鑑導航有未領取數量徽記。這能維持手機底部五欄導覽的可讀性。

## 8. 數值與節奏

### 8.1 目標時間

| 目標 | 預期累積遊玩時間 |
|---|---:|
| 發現 5 種魚並解鎖水族箱 | 30～45 分鐘 |
| 第一種魚達到熟悉 | 45～75 分鐘 |
| 發現 10 種魚並擴建水族箱 | 2～3 小時 |
| 第一種魚達到精通 | 2～4 小時 |
| 發現全部 20 種魚 | 6～10 小時 |
| 10 種魚達到精通 | 12～20 小時 |

上述時間是平衡方向，不要求以計時器強制控制。實際結果應透過測試存檔與模擬捕獲分布驗證。

### 8.2 經濟影響

- 閃光售價倍率與成就會增加金幣供給，但閃光數量有限，預估不會取代一般販售循環。
- 第二階段成就的固定金幣獎勵合計 780 金幣，低於一支強化遠投竿的 1480 金幣價格。
- 水族箱免費解鎖，避免新系統與現有裝備購買互相排擠。
- 若測試發現金幣過剩，優先新增非必要的收藏型消耗，不降低已承諾的成就獎勵。

### 8.3 防挫折規則

- 閃光存在明確保底，但 UI 不需要顯示精確倒數；圖鑑可用「水面似乎開始出現不同的光」提供柔性提示。
- 玩家永遠可以免費把魚從水族箱取回。
- 不新增漁獲箱容量上限。
- 成就與熟悉度不會因出售、換日或新版本下降。
- 新增資料缺失時使用安全預設值，不讓舊漁獲變成無法操作的物件。

## 9. 資料模型

### 9.1 存檔版本

實作時將 `SAVE_VERSION` 從 1 提升為 2。

### 9.2 捕獲標本

```js
{
  uid: "black_bream-...",
  fishId: "black_bream",
  length: 37.2,
  weight: 1.48,
  sizeTier: "large",
  variant: "normal", // "normal" | "shimmer"
  price: 194,
  caughtAt: "2026-07-16T...Z",
  context: {
    spotId: "reef",
    timeId: "dusk",
    weather: "rain",
    baitId: "shrimp",
    rodId: "light",
    day: 4
  }
}
```

舊漁獲遷移預設：`variant: "normal"`；缺少的 `context` 欄位設為 `null`，介面顯示「早期航海紀錄」。

### 9.3 圖鑑紀錄

```js
discovered[fishId] = {
  count: 6,
  firstCaught: "...",
  lastCaught: "...",
  bestLength: 37.2,
  bestWeight: 1.48,
  spots: ["reef"],
  times: ["dawn", "dusk"],
  weathers: ["sunny", "rain"],
  caughtShimmer: true,
  shimmerCount: 1,
  shimmerPity: 0
}
```

陣列欄位必須去重，並只接受目前資料表中存在的 ID。

### 9.4 水族箱

```js
aquarium: {
  fish: [/* 完整捕獲標本 */]
}
```

容量由發現魚種數即時計算，不寫入存檔，避免里程碑與容量不一致。

### 9.5 成就

```js
achievements: {
  first_catch: { completedAt: "...", claimed: true },
  shimmer_1: { completedAt: "...", claimed: false }
},
equippedTitle: "海灣旅人"
```

成就條件由當前狀態重新計算；存檔只保存完成時間與領取狀態。

## 10. 邏輯模組建議

本階段開始前，先將核心規則維持為可獨立測試的純函式。

建議新增或調整：


## 13. 完成本階段後再評估

完成 v0.2 並取得遊玩回饋後，依下列順序決定下一步：

1. 如果玩家喜歡追求特定魚：製作主題新海域與新魚種。
2. 如果玩家最常停留在船屋：增加水族箱觀察文字與家具互動。
3. 如果玩家只追求金幣：調整成就呈現與收藏目標，不先增加更多商品價格。
4. 如果閃光成為主要動機：再設計各魚種專屬特殊外觀，進入美術升級階段。
5. 如果玩家未注意熟悉度：改善捕獲結果與圖鑑進度回饋，而不是降低門檻。

第二階段完成的產品承諾是：玩家釣到的魚不再只是價目表上的一筆金幣，而會成為圖鑑、船屋與個人航海故事的一部分。
